### 0.1.4 当前实现校准

0.1.4 在 0.1.3 编辑体验基础上完成审查闭环：保存期间继续接收输入并在完成轮次前追平最新序列；关闭前截断 WAL 并以 generation 处理迟到命令；本地读取文件选择移入 Rust；恢复增加业务语义与 FTS 原文验证；活动数据根拒绝网络卷；字体启动校验哈希并迁移到 Fontations。数据库 schema、项目包和完整备份格式保持兼容。

以下 0.1.3 与 0.1.2 校准项继续有效：

- **恢复状态**：`prepared` 状态可由设置页取消，取消、重试、恢复切换和数据操作互斥；状态先撤销，暂存清理采用可重试、可由启动收敛的顺序。
- **编辑与复制**：当前正在编辑轮次的复制读取编辑器最新缓冲；其他轮次继续由 Rust/SQLite 提供。回收站操作先 flush，删除轮次后选择稳定的邻接项并清除失效锚点。
- **自动备份**：内容、结构、设置、导入、恢复和字体变更统一登记序列，5 秒防抖后检查备份；内容变更先等待最新编辑序列落盘。
- **Markdown 与 Windows**：零轮次可读包装、空草稿、UTF-16 文件名、保留设备名、控制字符、索引链接和纯复制拼接风险均有独立回归；项目包与完整备份格式不变。
- **大内容**：达到 2 MiB 的预览最多构造 256 Ki UTF-16 单元纯文本节点并显示截断说明；编辑、保存、复制和导出仍处理完整内容。
- **交互与测试**：嵌套弹窗只有顶层拥有模态语义；精确覆盖 1440×900、768×1024、390×844，并以等效 CSS 视口复核 100%/125%/150% 缩放。发布门禁限制 Vitest/Cargo/Tauri 最多 2 worker/job，E2E 为 1 worker。
- **前端构建**：为 Milkdown 间接依赖的 Vue esm-bundler 显式保留 Options API 并关闭生产 DevTools/hydration 详情；正式门禁不再产生 feature flags 告警，WYSIWYG chunk 原始大小减少约 1.96 KiB。
- **当前验证基线**：135 项 Vitest、81 项 Rust、21 项 Playwright 通过；27 项 Playwright 按视口/场景设计跳过，1 项 Rust 手动性能入口按设计 ignored。Prettier、ESLint、TypeScript、Web、Rustfmt、Clippy、Windows x64 Release、便携包二次解压、现有数据副本安全关闭、`pnpm audit` 和 RustSec vulnerability 门禁均通过。外部 Windows/DPI/IME/WebView2 边界不变。

### 0.1.1 实现校准（历史基线）

本节记录已经交付的真实实现，优先于下文仍以“目标方案”措辞描述但尚未完全落地的细节；不能用目标方案冒充已验收事实。

- **数据与并发**：SQLite 写连接由 Mutex 串行保护；Tauri 重 IO command 为异步。导入先在锁外暂存校验，搜索/导出/备份使用独立只读连接、在线快照或临时快照，不用一个全局锁包住全部 IO。
- **数据根**：支持 `--data-dir`、`VPR_DATA_DIR`、EXE 相邻 `data/`、locator 和原生选择器。`%LOCALAPPDATA%\VibePromptRecorder\` 还包含不含正文的 `initialization-locks/`。当前没有设置页“迁移数据目录”或按住 Shift 重选入口。
- **恢复与启动错误**：异常退出使用可写连接回放热 WAL 后执行检查。数据库/schema/恢复启动错误当前显示原生中文消息并退出，没有独立图形恢复页；不得把该目标页写成已交付。
- **设置**：`app_settings` 使用 `formatVersion = 1` 的整条 JSON 存储和字段级 patch 更新；未知字段拒绝，损坏值先备份到 `settings.broken.*` 再使用默认设置继续。
- **编辑与渲染**：WYSIWYG 通过 ProseMirror 真实 `docChanged` 事务识别用户修改；安全分析运行在 Worker。当前预检是保守启发式规则，不是完整 AST 等价证明。Shiki 仍在主线程，但超过 128 Ki UTF-16 单元时完整纯文本回退；达到 2 MiB 的轮次直接进入源码安全模式。
- **远程图片**：当前总超时 15 秒、连接超时 8 秒、上限 20 MiB、最多 4 次重定向，逐跳解析并固定 DNS，返回内存 data URL；安全上明确禁用系统代理。
- **字体**：解析使用 `skrifa (Fontations) + wuff`，协议为 `vprfont://` 与 `vprasset://`；启动会对账登记/文件/大小/哈希并卸载不再使用的导入字体。EXE 相邻“字体/”批量导入入口尚未实现。
- **搜索**：1～2 个 Unicode 标量值防抖 500 ms，3 个及以上 120 ms；当前一次返回有界结果，不提供继续加载/预览层。flush 失败会停止搜索并提示，不把未保存缓冲伪装成后端结果。
- **归档与恢复**：结构化项目 Markdown 当前始终导出单文件；恢复状态为 `prepared → old-moved → 删除状态文件即提交`。长期保留的是 `backups/manual/recovery-before-*`，成功后的 `restore-*` / `old-*` 是可清理工作目录。
- **性能数据流**：当前 `list_rounds` 返回全部轮次摘要及最多 8192 单元预览，不是“每页 50 + 32 MiB 正文 LRU”；时间线仍由 React Virtuoso 只渲染可见卡片。
- **发布与验证**：`pnpm verify` 不包含 Playwright；个人自用/正式打包脚本会单独运行 E2E。最终本机基线为 102 项 Vitest、66 项 Rust 通过（另 1 ignored）、14 项 Playwright 通过（另 10 按视口跳过）、Clippy `-D warnings`、Web 和 Windows x64 Release 构建通过；收尾阶段第二次完整复核保持相同通过数量与 0 失败。
- **未关闭的外部边界**：真实五档 DPI、真人微软拼音、Win10/另一台 Win11 冷热启动与恢复、WebView2 物理缺失仍待外部验收。个人自用成品可交付；正式公开发布门禁继续阻断这些项目被误标为通过。

## 2. 已冻结的产品范围

### 2.1 必须实现

1. Windows 本地、单用户、无需账号、核心功能离线。
2. 按项目管理多轮提示词，只记录用户提示词，不记录 AI 回答。
3. 每个项目包含多轮正式提示词以及一个当前草稿。
4. 默认 Markdown 所见即所得编辑，并可切换完整 Markdown 源码模式。
5. 完整支持 CommonMark 和 GFM 常用语法、代码块及安全渲染。
6. 项目和轮次自动保存、全文搜索、复制、排序、删除、撤销与恢复。
7. 左侧紧凑时间线、保存时间、显眼轮次序号、默认五行折叠预览。
8. 固定详情编辑区，展开长提示词时不改变时间线卡片高度和滚动位置。
9. 深色与多种浅色主题。
10. 界面、正文、代码分别支持字体、字号、粗细和行高设置。
11. 支持内置字体、Windows 系统字体及用户导入字体。
12. 窗口置顶、窗口与编辑状态恢复。
13. Markdown 导入导出、无损项目包、完整备份与安全恢复。
14. 免安装便携运行，数据与程序一起迁移。
15. 全部界面、状态、错误和使用说明默认使用简体中文；时区跟随当前 Windows，界面时间统一使用本文定义的中文友好格式，不随系统区域的短日期样式变化。

### 2.2 首版不实现

1. AI 优化、生成、总结或模型 API。
2. AI 回答记录。
3. 登录、云同步、团队协作、社区、插件系统。
4. 数学公式、Mermaid、脚注、自动目录、YAML Front Matter、GitHub Alerts。
5. 图片上传、粘贴存储、附件管理。
6. Word/RTF/HTML 文档编辑和脱离 Markdown 的富文本数据格式。
7. 标签、双向链接、多级文件夹。
8. 自动读取终端、代码项目或剪贴板。
9. 自动更新、公共发布、代码签名、ARM64 构建。
10. 数据库密码、应用启动密码或内置数据加密；个人版依赖 Windows 账户权限和磁盘加密。

## 3. 默认产品决策

### 3.1 项目规则

1. 首次启动自动创建并打开 `Vibe Coding 项目-1`。
2. 自动项目编号使用持久递增计数器，删除项目后不复用旧编号。
3. 允许同名项目；名称去除首尾空格，空名称触发自动命名，最长 120 个 Unicode 字符。
4. 置顶项目排在前面；置顶组和普通组内部各按最近使用时间倒序排列。
5. “最近使用”由打开或编辑触发，单纯复制不改变排序。
6. 项目排序在用户完成一次交互后刷新，避免正在点击时列表突然跳动。

### 3.2 草稿与正式轮次

1. 每个未删除项目始终且只能有一个当前草稿。
2. 输入停顿 300 毫秒后，把当前轮完整 Markdown 直接写入主数据库并等待落盘确认（WAL + `synchronous=FULL`）；单轮超过 512 KiB 时防抖放宽到 1 秒。中文输入法只在组合文字正式上屏后才触发保存计时。
3. 点击或按快捷键“下一轮”时：

   - 非空草稿被固化为正式轮次，记录首次保存时间。
   - 随后在项目末尾创建新的空草稿并聚焦。
   - 仅含空白字符的草稿不创建空轮次，只给轻量提示。

4. 历史正式轮次可以继续编辑；首次保存时间不变，只更新最后修改时间。
5. 草稿固定在正式轮次末尾，不参与拖动排序。
6. 用户正在编辑历史轮次时，“下一轮”先强制保存该轮，然后切换到当前草稿；不会把历史轮再次固化。
7. 当前草稿不作为独立轮次移入回收站；其“删除”操作实际为清空同一草稿，显示 8 秒撤销，并保留短期恢复快照。

### 3.3 删除与撤销

1. 项目和正式轮次删除均为软删除；清空当前草稿按 3.2 的专用规则处理。
2. 删除后显示 8 秒撤销提示，同时在回收站持续保留，直到用户逐项确认永久删除。
3. 回收站支持恢复和永久删除；永久删除必须确认。
4. 文字撤销由当前编辑器负责。
5. 删除、恢复和排序使用结构操作撤销栈，单次会话最多保留 100 个操作。
6. 编辑器有焦点时 `Ctrl+Z` 只撤销文字；列表或结构控件有焦点时才撤销结构操作。

### 3.4 复制规则

1. “复制当前轮”复制该轮完整 Markdown 原文。
2. 代码块复制按钮只复制代码正文，不包含围栏和语言标记。
3. “复制全部”包含全部正式轮次及非空当前草稿，按当前显示顺序输出；每一轮 Markdown 原文字节（除剪贴板统一使用 LF）在边界内保持不变。
4. 复制菜单提供“带轮次标签（默认）”和“纯原文拼接”两种格式。默认格式为供 AI/文本工具识别的多段文本载荷，不宣称把任意多份 Markdown 合成一份可独立渲染的 Markdown 文档：

   ```text
   ===== 第 1 轮 =====
   <Markdown 原文>

   ===== 第 2 轮 =====
   <Markdown 原文>
   ```

   非空草稿在末尾使用 `===== 当前草稿 =====`，不伪装成下一轮编号。

5. 复制不创建下一轮，也不改变项目最近使用时间。
6. 所有复制操作统一走 Tauri 剪贴板接口（Rust 端 clipboard-manager 插件，仅开放写文本权限），不依赖网页端 `navigator.clipboard`；10 MiB 级文本复制不得卡顿或截断，失败时保留内容并提供“重试”。
7. 纯原文拼接只在轮次之间加入两个换行。复制前分别解析每一轮；若发现未闭合围栏、原始 HTML 块等可能跨越边界的结构，显示一次说明，但仍保证各轮原文不被自动补围栏、转义或改写。需要无歧义地保存轮次边界时使用 `.vcpproject`。

## 4. 目标平台与便携版约束

### 4.1 支持范围

1. Windows 10 22H2 或 Windows 11，x64。
2. 单实例运行；重复启动时激活已有窗口。
3. 精简个人便携包使用系统 WebView2 Evergreen Runtime。当前目标电脑已检测到 `150.0.4078.83`；每次候选构建仍重新检查，不把该版本写成固定依赖。
4. 不要求管理员权限，不写入系统字体目录，不强制写注册表。
5. 不提供安装程序；交付物为一个可解压运行的便携目录压缩包。
6. 支持环境定义为“目标 Windows + 可用 WebView2 Runtime”。缺失时由 Rust 启动壳在创建 WebView 前显示中文说明和退出按钮，不静默联网下载；如未来要在无运行时电脑使用，另行生成包含 Fixed Version Runtime 的完整离线便携包并单独核算体积，本个人首版不默认交付该大包。

### 4.2 便携目录


规则：

1. 程序目录可写且相邻 `data/` 不存在或为空时，先在 `%LOCALAPPDATA%\VibePromptRecorder\initialization-locks/` 获取候选路径侧锁，再创建目录并以 UUID 临时文件原子发布 marker。非空但没有有效 marker 的同名目录不得认领或覆盖；启动只清理名称严格匹配的 marker/write-probe 孤儿。
2. WebView2 用户数据目录显式指向 `data/webview2/`，避免散落到系统其他位置。
3. 程序目录不可写时，在主窗口创建前打开原生目录选择器。用户选择的路径记录在 `%LOCALAPPDATA%\VibePromptRecorder\locators\<规范化EXE目录-SHA256>.json`；它只含版本和数据路径。系统目录中的另一落点是 `initialization-locks/` 侧锁，两者都不含提示词正文。
4. 数据根目录必须在窗口创建前完成可写、可创建、可重命名和剩余空间检查。
5. 首版拒绝把活动数据库放在 UNC 路径或 Windows 判定为 Remote 的卷上，因为 WAL 依赖同机共享内存语义；提示用户选择本地固定盘或本机可写的可移动盘。备份和导出目标可以是网络位置。
6. 数据根位于 OneDrive、Dropbox 等已知同步目录内（按 `%OneDrive%` 环境变量及常见路径特征判断）时，显示一次性中文提醒“同步软件可能与数据库文件冲突，建议移到不被同步的目录”，允许继续但记录该状态；README 使用说明中同样写明。
7. 整体移动便携目录前必须完全退出应用及其 WebView2 子进程。
8. 所有相对资源与数据路径都从 `current_exe()` 的父目录解析，禁止依赖启动时工作目录（CWD）；全链路必须正确处理含中文、空格及超过 260 字符的长路径。
9. `tauri.conf` 不自动声明主窗口。原生启动入口先通过 WebView2 Loader 可用性查询做无业务数据写入的运行时预检；缺失时立即显示原生中文消息框并退出，不创建或认领 `data/`。预检通过后，Rust `setup` 才确定数据根、处理待恢复状态并读取窗口设置，再通过 `WebviewWindowBuilder` 指定 `data/webview2/` 创建隐藏窗口，前端就绪后显示。
10. 数据根解析优先级固定为：受控启动参数 `--data-dir` → `VPR_DATA_DIR` → EXE 相邻 `data/`（验证或按规则 1 初始化）→ 当前 EXE 目录哈希对应的定位文件 → 原生选择器。任一路径都必须经过 UNC、本地可写性、marker 和独占锁验证；设置页迁移/重置与按住 Shift 重选是未来能力，0.1.1 不宣称已实现。
11. 把备份恢复到用户选择的新数据根时生成新的实例 UUID marker，不能从备份覆盖目标 marker；整体复制已有便携目录时则保留原 marker，数据内容不变。

## 5. 技术选型

| 层级         | 选型                                    | 执行约束                                                                               |
| ------------ | --------------------------------------- | -------------------------------------------------------------------------------------- |
| 桌面外壳     | Tauri 2.x                               | 仅开放实际需要的能力权限；不启用更新器、Shell 和网络插件                               |
| 前端         | React + TypeScript + Vite               | TypeScript 严格模式；不使用 CDN                                                        |
| UI 状态      | Zustand                                 | 只保存界面状态；业务真相来自 Rust/SQLite                                               |
| 所见即所得   | Milkdown Crepe                          | 只启用 CommonMark/GFM、工具栏、列表、表格、CodeMirror 代码块；关闭 AI、LaTeX、图片上传 |
| 源码编辑     | CodeMirror 6                            | 显示完整 Markdown；支持查找、撤销、中文 IME                                            |
| 只读渲染     | react-markdown + remark-gfm             | 与独立安全净化层组合；历史卡片不挂载富文本编辑器                                       |
| 代码高亮     | Shiki 精简语言包（JavaScript 正则引擎） | 按需加载；未知语言回退纯文本；不携带 WASM 引擎                                         |

| 原生业务层   | Rust                                    | IPC 参数和返回值全部强类型化                                                           |
| 本地数据库   | SQLite（rusqlite `bundled` 自带稳定版） | 静态编译进 EXE，单写队列、WAL、FTS5；不链接机器 SQLite DLL                             |
| 序列化       | serde                                   | 备份和 IPC 使用显式版本结构                                                            |
| 日志         | `diagnostics.rs` 最小本地日志与轮转     | 禁止记录提示词正文、剪贴板内容和导入文件正文                                           |
| 前端测试     | Vitest + Testing Library                | 组件、状态和虚拟列表测试                                                               |
| Rust 测试    | cargo test                              | 数据库、迁移、备份、恢复、搜索和路径安全测试                                           |
| 端到端       | Playwright Web 测试 + Windows 实机冒烟  | Web 交互与 Tauri 原生能力分别验证                                                      |

选型依据：

- Milkdown 原生提供 CommonMark/GFM 所见即所得编辑、Markdown 获取、历史和 CodeMirror 代码块能力，使用 Builder 方式只装载需要的功能。
- React Virtuoso支持动态尺寸、滚动位置恢复及大量记录虚拟化，适合固定时间线加独立详情面板。
- SQLite FTS5 trigram 支持通用子串检索；不足三个字符的查询使用参数化 `LIKE` 回退。
- SQLite 在线备份 API 或 `VACUUM INTO` 用于活动数据库备份，禁止直接复制正在使用的 WAL 数据库文件。

依赖管理：

1. 主版本按上表固定，具体补丁版本在首次搭建时选择最新稳定版并写入 lockfile。
2. 不使用带 Beta 标记的核心 Markdown 数据转换能力。
3. 每次依赖升级必须通过 Markdown 往返、中文 IME、数据库迁移和便携构建测试。
4. 构建时生成第三方依赖和字体许可清单。
5. SQLite 直接使用 rusqlite `bundled` 特性自带的稳定版本（当前为 3.53.2），由 lockfile 锁定，不自行维护 SQLite 源码或补丁。启动与发布检查断言 FTS5 编译选项存在且 trigram 建表成功；rusqlite 升级按第 3 条回归后才进入 lockfile。

```text
React UI
  ├─ 项目导航 / 时间线 / 详情编辑器 / 搜索 / 设置

  └─ Typed IPC Client
            │
            ▼
Tauri Commands（严格白名单）
            │
            ▼

  ├─ ProjectService
  ├─ RoundService
  ├─ SearchService
  ├─ BackupService
  ├─ ImportExportService
  ├─ FontService
  ├─ WindowService
  └─ RecoveryService
            │
            ▼
Repository + 单写入队列
  ├─ SQLite
  ├─ 版本化备份包
  ├─ 私人字体目录
  └─ 最小化无正文日志
```

### 6.1 架构原则

1. SQLite 和文件系统操作只由 Rust 执行，前端不能直接拼接 SQL 或访问任意路径。
2. SQLite 写连接由 Rust Mutex 串行保护，每个业务写操作使用事务；导入、归档和文件校验先在锁外执行，搜索/导出/备份使用独立只读连接或一致性快照。
3. 前端可以持有未保存编辑缓冲，但数据库是已确认保存状态的唯一来源。
4. 任何时刻最多挂载一个 Milkdown/CodeMirror 主编辑器；历史轮次只使用轻量只读 Markdown 预览。
5. IPC 以命令为单位，例如 `finalize_draft`、`reorder_rounds`，不暴露通用 SQL 和通用文件读写。
6. 所有实体使用稳定 UUID；界面轮次序号只由当前排序计算。
7. 所有时间以 UTC 毫秒存储，显示时转换成 Windows 本地时区。

使用 `key + versioned_json_value` 保存：

- 主题、窗口置顶、上次项目。
- 五行折叠设置、轮次序号开关。
- 界面/正文/代码字体、字号、粗细、行高和回退顺序。
- 字体收藏、最近使用字体。
- 自动备份上次执行时间及项目自动编号计数器。
- 项目栏宽度、时间线宽度、用户手动折叠状态和响应式布局前状态。

窗口大小、位置、最大化状态和显示器标识直接写入便携 SQLite，不使用会默认落到系统配置目录的 window-state 插件。设置主体包含 `formatVersion = 1`，由字段级 patch 更新并拒绝未知字段；损坏主体先备份为 `settings.broken.*`。恢复窗口时检查其仍位于当前显示器可见区域。

### 7.5 `font_registry`

记录用户导入字体，不保存字体正文：

- `id`、SHA-256、来源、显示名称、内部族名。
- 文件名、格式、文件大小、实际 face 数。
- 字重、样式、宽度、可变轴。
- 导入时间、是否可用、错误状态。

### 7.6 `schema_migrations`

记录数据库版本、应用版本、执行时间和迁移校验。迁移必须：

1. 先创建自动备份。
2. 在事务中执行。
3. 失败时回滚并保留旧数据库。
4. 不允许新版本失败后继续写入未知结构。

### 7.7 搜索索引

建立 FTS5 trigram 搜索表，索引项目名称、未删除轮次的 Markdown 原文和轮次备注，同时保存不参与索引的项目 ID、轮次 ID。

1. Unicode 标量值长度达到 3 时使用 trigram 搜索。
2. 长度为 1～2 的中文、英文、数字、符号或 Emoji 一律使用转义后的参数化 `LIKE`，不能只对中文回退。
3. 英文默认忽略大小写。
4. 搜索包含代码块内容。
5. 项目改名、轮次保存、删除和恢复在同一事务中同步索引。
6. 搜索片段先作为纯文本处理，再由前端安全高亮，数据库标记不得直接当 HTML 注入。
7. trigram 以更大的索引体积和保存时同步更新成本换取中文/代码通用子串搜索；单轮正文上限仍为 10 MiB。发布验收至少记录数据库正文与 `search_index` 的页数/字节占比、全量重建耗时和 D1/D2 首批搜索延迟。0.1.4 不改 tokenizer、不延迟索引一致性；若索引超过主数据 4 倍、重建超过 30 秒或 D2 P95 超过 300 毫秒，再立项评估外部内容表、批量重建或替代分词。

## 8. 保存、恢复与数据一致性

### 8.1 自动保存

```text
已保存 → 用户输入 → 待保存（防抖 300ms） → 主库写入中 → 已保存
                                        └→ 失败 → 保留内存缓冲并持续警告
```

1. IME `compositionstart` 至 `compositionend` 之间不触发保存；`compositionend` 后重新计时。
2. 防抖到期后，把当前轮完整 `content_md` 连同 `round_id + expected_revision` 交给 Rust 单写队列，在一个事务内更新内容、`updated_at`、`revision` 和搜索索引；`synchronous=FULL` 保证提交即落盘。
3. Rust 成功提交后返回新 revision 和保存时间，前端才显示“已保存 HH:mm:ss”；提交前显示轻量“正在保存”状态，不打扰输入。
4. 保存与 Markdown 解析、代码高亮互不等待，不阻塞编辑器绘制；连续输入期间最多每个防抖窗口提交一次，单轮超过 512 KiB 时窗口放宽到 1 秒。
5. revision 不符（理论上仅可能出现在恢复、导入等维护操作与编辑竞争时）不覆盖：保留数据库版与当前缓冲，进入 8.5 的冲突界面。
6. 切换项目、切换轮次、创建下一轮、删除/恢复实体、重排、搜索索引重建、导入导出、备份、schema 迁移、数据目录切换和正常退出前，必须先同步 flush：立即执行未到期的防抖保存并等待落盘确认；失败时阻止会产生不完整快照或覆盖的操作，但仍允许切换源码模式、复制和应急导出。
7. 保存失败时编辑器内容完整保留在内存，顶部持续显示“内容尚未安全保存”，处理方式见 8.3；绝不把未落盘内容标成“已保存”。

耐久边界：正常关闭和可处理的异常退出经退出 flush 后不丢任何内容；程序崩溃、系统强杀或断电的最坏情况丢失最近一个防抖窗口（约 0.3～1 秒）内的输入。数据库文件本身依赖 SQLite WAL 日志保证崩溃后自动恢复到最近一次完整事务，不会半写损坏。

### 8.2 SQLite 设置

1. `journal_mode=WAL`。
2. `foreign_keys=ON`。
3. 首版固定 `synchronous=FULL`，不得为了跑分改成 `NORMAL/OFF`；未来若改变必须重新定义断电恢复边界并经用户批准。
4. 保留自动 checkpoint；后台只做非阻塞的 PASSIVE/best-effort checkpoint。在线备份不要求先 FULL/TRUNCATE checkpoint，输入写队列禁止执行会等待读者的阻塞式 checkpoint。
5. 启动时验证 SQLite 版本和编译选项包含 FTS5。
6. 异常退出后执行快速完整性检查；检测到问题时进入只读恢复模式。
7. 启用 `SQLITE_DBCONFIG_DEFENSIVE`，所有查询参数化，应用不接受用户提供的 SQL。

### 8.3 写入失败

磁盘满、目录只读、文件锁定或数据库错误时：

1. 编辑器内容继续保留在内存，不清空、不切换到空内容。
2. 顶部显示持续但不遮挡的“保存失败”状态。
3. 提供“重试保存”“复制未保存内容”“导出恢复文件”；恢复文件包含当前内存缓冲的完整 Markdown。
4. 禁止继续执行导入、恢复或永久删除等高风险写操作。
5. 日志仅记录错误码、路径类别和实体 ID，不记录提示词正文。

### 8.4 启动恢复

1. 获取数据目录独占锁，在创建 WebView2 前先完成待恢复/待迁移目录操作；按完成标记幂等地继续或回滚中断的切换（见 18.5）。
2. 读取 clean-shutdown marker。异常退出时以可写连接先让 SQLite 回放热 WAL，再执行 `quick_check`；失败时不创建空库覆盖现场，显示原生中文错误并退出。正常启动只做 schema/header 快速检查。
3. 需要 schema 迁移时先创建迁移前一致性快照，再执行事务化数据库迁移和迁移后 `quick_check`。未知新 schema 或检查失败显示原生错误并退出；独立图形恢复页仍是未来目标。
4. 清理已确认完成且无引用的临时文件，保留未确认恢复文件、冲突版本和旧目录。
5. 恢复窗口、主题、字体、上次项目、轮次、编辑模式及编辑/详情/时间线锚点。
6. 上次轮次已被删除时，依次降级到当前草稿、最近正式轮次、项目空状态。
7. 多显示器变化导致窗口离屏时，将窗口纠正到主显示器可见范围。

迁移或恢复切换属于维护启动，显示原生进度并从普通冷启动 2 秒指标中单独统计，不能为了达标跳过检查。

### 8.5 冲突与数据库损坏界面

revision 冲突时（正常编辑流程不会出现，仅可能由恢复、导入等维护操作与未 flush 编辑竞争引起），停止对该轮自动写回，同时保留数据库版和本地缓冲版。0.1.1 比较界面并排显示双方全文、时间、长度和哈希（尚无逐行 diff），提供：

1. **保留两份（默认）**：数据库版留在原轮，本地版作为紧邻的新正式轮次保存，并写入 `recovered_from_round_id`。
2. **用本地版替换**：先创建恢复点，再覆盖原轮。
3. **保留数据库版**：放弃本地缓冲前二次确认，并重新挂载数据库正文。

数据库损坏、未知 schema 或迁移失败时不进入看似可编辑的普通主界面，也不自动新建空库。0.1.1 当前在创建业务窗口前显示原生中文原因并退出；独立只读恢复页及“仅导出并退出”是未来增强项。

## 9. 主窗口与响应式布局

### 9.1 顶部操作区

主窗口关闭 Windows 原生装饰，避免系统深色标题栏与应用主题割裂。应用顶部栏默认高 58 个逻辑像素（窄窗口 54），名称、项目名称及空白区域支持拖动和双击最大化；右侧提供最小化、最大化/还原与安全关闭，关闭仍必须先完成同步保存。顶部栏同时包含：

- 新建项目。
- 全局搜索。
- 当前项目名称和保存状态。
- 主题快速切换。
- “窗口始终置顶”开关。
- 设置。
- 窗口最小化、最大化/还原和关闭。

所有纯图标按钮必须有简体中文提示、可见焦点和快捷键说明。“窗口始终置顶”与项目的“固定在顶部”必须使用不同图标和完整名称。

### 9.2 宽窗口三栏布局

窗口宽度不小于 1200 时：

| 区域       | 默认宽度 |   可调范围 | 内容                               |
| ---------- | -------: | ---------: | ---------------------------------- |
| 项目栏     |      236 |   200～340 | 置顶项目、最近项目、新建与项目菜单 |
| 轮次时间线 |      340 |   280～460 | 折叠轮次卡、时间、序号、草稿       |
| 详情区     | 剩余空间 | 不低于 460 | 完整阅读和唯一活动编辑器           |

项目栏和时间线可拖动调整宽度，栏宽及手动折叠状态自动保存。

### 9.3 中等与窄窗口

1. 宽度 880～1199：项目栏变为抽屉，时间线和详情保持并排。
2. 宽度小于 880：先显示时间线，点击轮次后进入覆盖式详情抽屉；详情头部提供“返回轮次”。
3. 最小窗口尺寸为 680×520 个逻辑像素。
4. 自动响应式折叠不覆盖用户在宽窗口下保存的栏宽和折叠偏好。
5. 小窗口中所有核心操作必须可见或通过明确菜单进入，不能只依赖悬停。

### 9.4 项目栏

项目项显示名称、正式轮次数量、最近修改时间、置顶和选中状态。超长名称单行省略，悬停显示完整值。

项目菜单提供：

- 重命名。
- 固定/取消固定在顶部。
- 导出项目。
- 移入最近删除。

删除当前项目后优先选中相邻项目；删除最后一个项目后进入明确空状态，不立即偷偷新建替代项目。用户再次点击新建时继续使用单调递增编号。

## 10. 时间线、折叠与导航

### 10.1 时间线卡片

时间线标题区固定显示当前轮数，并提供直接执行默认“带轮次标签”的“复制全部”分裂按钮；箭头菜单可改用“纯原文拼接”或进入复制设置。该按钮在窄窗口仍是一级可见操作，不藏入多层菜单。

1. 正式轮次按用户排序显示，当前草稿固定在底部。
2. 默认每张卡展示 5 个渲染后的视觉行；设置至少提供 1～20 行和“不折叠”。
3. 卡片展示：

   - 高对比度“第 N 轮”徽标。
   - 备注非空时在徽标旁以区块标题层级显示单行备注（超长省略，悬停见全文）。
   - Markdown 安全渲染摘要。
   - 首次保存时间。
   - 编辑后显示最后修改时间。
   - 复制、删除和拖动手柄。

4. 当前草稿显示“草稿 · 已自动保存 HH:mm:ss”，不作为正式轮次编号。
5. 选中正式轮次时明显显示“当前：第 N 轮 / 共 M 轮”；选中草稿时显示“当前：草稿 / 共 M 轮”。草稿不计入 M，非空时另显示“+ 草稿”。
6. 序号只表示当前顺序，删除或调序后重新计算；所有定位使用稳定 ID。

正式轮次的主时间格式为 `YYYY-MM-DD HH:mm`，编辑过则在下方补充“修改于 …”；悬停或键盘聚焦显示包含秒数和时区的完整创建、正式保存、修改时间。

折叠按渲染后的物理高度实现：卡片预览采用统一的紧凑行高网格，容器最大高度为“设置行数 × 当前预览行高”，溢出裁切并显示渐隐层；标题、列表、引用、表格和代码仍保留可辨识样式。不得根据 Markdown 原文换行符数量截字符串，也不得生成残缺 HTML。

折叠卡是完全惰性的只读摘要：任务复选框禁用，链接、远程图片加载和代码复制不在卡内激活，表格与长代码不产生嵌套滚动条；卡片正文任意位置统一打开详情。复制/删除/拖动只存在于卡片外层操作区。选择“不折叠”会移除预览高度限制并允许卡片变高，但普通点击“打开详情”永远不改变卡片高度。

### 10.2 展开策略

“展开”不使用原地无限增高：

1. 点击卡片后在固定详情区显示完整内容。
2. 宽窗口更新右侧详情；窄窗口打开详情抽屉。
3. 时间线卡片高度、其他卡片状态和滚动锚点不改变。
4. `Esc` 关闭详情时，焦点回到原卡片。
5. 当前草稿可默认在详情区打开，历史卡片继续保持紧凑。

状态明确分为 `focusedRoundId`（当前键盘焦点）、`selectedRoundId`（高亮并计入“当前 N/M”）和每项目持久化的 `detailOpen`：

1. 单击卡片或“展开”会选中并打开详情；详情头部始终有可见的“收起详情”按钮。
2. 时间线 `↑/↓` 改变选中轮次；详情已开时同步更新右侧内容，详情已收起时不自动打开。
3. `Enter/Space` 打开详情；详情已经打开时把焦点送入阅读区或编辑器。
4. 收起详情不取消选中。宽窗口保留详情栏尺寸并显示轻量占位，避免时间线宽度重排；窄窗口关闭抽屉并把焦点和滚动锚点还给原卡片。
5. 切换或收起前先执行同步保存（8.1 的 flush）；保存故障不丢内存缓冲，也不允许旧详情响应覆盖新选中轮次。
6. “复制当前轮”保留在详情头部；“完成并新建下一轮”只在正文输入顶部保留一个主按钮，历史轮对应“回到当前草稿”。窄窗口重新排布工具栏，不能裁切模式选择或主操作。
7. 详情头部提供可选的单行备注输入（占位文字“添加备注…”，最长 120 字符，随自动保存持久化）；详情状态行以辅助层级持续显示当前轮字符数（Unicode 字符计数，编辑时节流刷新，不参与保存判定）。

### 10.3 虚拟化

1. 使用 React Virtuoso，只渲染可见项及小范围缓冲。
2. 卡片内部使用 padding，不使用会逃逸测量边界的上下 margin。
3. 字体加载、窗口缩放和折叠行数变化后触发重新测量。
4. 重新测量前记录锚点轮次 ID 和相对偏移，完成后恢复，不能产生明显跳位。
5. 高速滚动时允许暂缓非关键代码高亮，但不得显示白屏或错误内容。
6. 新轮次仅在用户原本位于底部时自动带入视口；用户正在浏览历史时显示“有新轮次”入口，不突然跳到底部。

### 10.4 鼠标与键盘

1. 鼠标滚轮使用 Windows/WebView2 原生滚动，不做持续 JavaScript 平滑劫持。
2. 时间线获得焦点时：

   - `↑` / `↓` 选择上一轮或下一轮，并短时平滑带入视口。
   - `PageUp` / `PageDown` 翻页。
   - `Home` / `End` 到首轮或末尾草稿。
   - `Enter` 打开详情。

3. 编辑器有焦点时，上述按键保持文字光标的标准行为。
4. `Alt+Shift+↑/↓` 在时间线中移动当前正式轮次。
5. 滚动超过一个视口后显示“一键回到顶部”悬浮按钮；`Alt+Home` 提供相同操作。两者只移动当前项目时间线，不改变选中轮次、详情、编辑内容或焦点。
6. 程序化定位动画控制在 120～180 毫秒；Windows 开启减少动画时立即定位。

## 11. Markdown 编辑与渲染

### 11.1 支持基线

首版语法基线固定为 CommonMark 0.31.2 与 GFM 0.29-gfm，不随依赖升级静默改变。支持：

- H1～H6、段落、软/硬换行、分隔线。
- 粗体、斜体、粗斜体、删除线。
- 有序、无序、嵌套、任务列表。
- 引用、链接、引用链接、自动链接、转义和实体。
- 表格与对齐。
- 行内代码、缩进代码块、反引号和波浪线围栏代码块。
- Unicode、中文、Emoji 和常见标点。

不支持的扩展以安全原文保留；用户点击后切换源码模式编辑，不能静默丢弃。

### 11.2 双模式编辑会话

详情区提供：

1. 所见即所得：默认模式，基于 Milkdown Crepe。
2. Markdown 源码：基于 CodeMirror 6，可完整控制原文。

每次打开轮次建立编辑会话：

```ts
type EditorSession = {
  roundId: string;
  originalMarkdown: string;
  currentMarkdown: string;
  mode: "wysiwyg" | "source";
  dirty: boolean;
  clientSequence: number;
  persistedSequence: number;
  revision: number;
  composing: boolean;
};
```

规则：

1. 仅打开、查看或切换模式且没有编辑时，返回源码必须逐字符等于原文。
2. 所见即所得发生真实编辑后允许把等价 Markdown 标记规范化，但不得改变文字语义、代码正文和缩进、URL、列表层级或表格数据。
3. ProseMirror JSON 和渲染 HTML 不得持久化为提示词内容。
4. 源码进入所见即所得前先在内存副本解析；失败时原文保持不变并留在源码模式。
5. `compositionstart` 至 `compositionend` 期间禁止序列化、保存或重建编辑器；模式、轮次、字体及“下一轮”请求进入单个待执行队列，在候选文字上屏后按最后一次请求安全执行。
6. 切换轮次前强制 flush，旧轮次的迟到保存响应不得覆盖新轮次。

进入所见即所得前在 Web Worker 中做**保守能力预检**（只读、不写库）：检测 YAML Front Matter、脚注、GitHub Alerts、自定义指令、数学语法、未闭合代码围栏、不受支持/不安全的原始 HTML，以及 2 MiB 超大阈值。命中任一规则即标为 `source_only`，显示原因并保留安全预览与完整源码编辑；规则与金样语料随解析器升级回归。

完整 AST 语义等价比较仍是长期目标，0.1.1 不把它伪装成已实现。当前写回规则为：

1. 未发生真实文档事务的打开和模式切换复用原始 Markdown，逐字符不变。
2. 自定义 ProseMirror 插件只把 `create()` 完成后的 `docChanged` 事务标记为用户变更；初始化阶段的规范化事务即使在防抖后回调也不写回。
3. 菜单命令、块操作和真实输入产生的文档事务按 Crepe 序列化结果写回；生命周期创建/销毁失败会停止编辑器写回、显示源码恢复提示并保留 store 中原文。

### 11.3 Milkdown 功能裁剪

启用：

- CommonMark、GFM。
- History、Clipboard、Cursor、Indent。
- Toolbar、列表、链接、表格、CodeMirror 代码块。

0.1.1 使用 Crepe 提供的 BlockEdit、Toolbar、列表、链接、表格和 CodeMirror 代码块能力，并由应用工具栏始终提供所见即所得/源码/安全预览切换。具体富文本按钮顺序和选区禁用规则沿用当前 Crepe 稳定实现；完整定制工具栏与逐按钮状态矩阵仍是后续目标，不作为本版验收声明。

禁用：

- AI。
- LaTeX。
- 图片上传、拖入图片和粘贴图片生成附件。
- 协作、远程资源和不需要的插件。

### 11.4 代码块

常用高亮语言白名单：

```text
plaintext, json, javascript, typescript, jsx, tsx,
html, xml, css, scss, shell, powershell, python,
java, c, cpp, csharp, go, rust, sql, yaml, markdown,
diff, dockerfile, toml
```

1. 未知语言原文显示，不报错。
2. 保留全部空格、Tab、缩进和换行。
3. 长行默认横向滚动，并提供当前用户设置的自动换行开关。
4. 每个代码块显示语言名和复制按钮。
5. 代码块永远不能作为 HTML 或脚本执行。
6. Shiki 语言在主线程按需加载；单代码块超过 128 Ki UTF-16 单元时不运行 Shiki，完整转义为纯文本并提示，从而避免高亮阻塞输入。

### 11.5 HTML、链接与图片

1. 原始 HTML 只渲染固定 schema v1：`p, br, strong, em, s, del, blockquote, ul, ol, li, h1`～`h6, hr, code, pre, table, thead, tbody, tr, th, td, a, details, summary, kbd`。
2. 属性只允许：链接的 `href/title`、有序列表的受限整数 `start`、表格单元格的受限整数 `colspan/rowspan` 与枚举 `align`。禁止 `style`、`class`、`id`、脚本、iframe、事件属性、危险 SVG、`javascript:`、`file:` 和其他协议；URL 经过统一规范化后再判定。
3. 外部链接显示真实目标，交给系统浏览器打开，应用 WebView 不导航到外部页面。
4. 所见即所得编辑器中单击链接只定位光标并打开编辑浮层；只有浮层“打开链接”或 `Ctrl+单击` 才进入外部确认。详情只读视图中单击链接可直接进入显示完整域名的确认流程。
5. 远程图片默认零请求，只显示替代文本、域名和“临时加载”。
6. 用户逐张主动加载时，由 Rust 发起无 Cookie、无 Referer、无系统代理的一次性请求；限制 HTTP/HTTPS、15 秒总超时、8 秒连接超时、20 MiB、最多 4 次重定向和有效图片 MIME，并逐跳拒绝回环及内网地址。
7. 图片只以内存 data URL 返回当前 WebView，不写入项目、不做附件缓存。

### 11.6 Markdown 验收语料

建立版本控制下的金样目录：

- CommonMark/GFM 语法样例。
- 未闭合围栏、嵌套反引号、超长行、空文档。
- 中文、Emoji、组合字符和不同换行符。
- HTML/XSS/危险 URL 样例。
- YAML、脚注、GitHub Alerts、自定义指令、复杂原始 HTML、畸形表格和未闭合结构的 `source_only` 判定。
- 源码→所见即所得→源码无操作往返。
- 所见即所得实际编辑后的语义等价比较。

### 11.7 粘贴与拖放

1. 源码模式由 CodeMirror 按文本处理粘贴；应用不主动读取或持续监听剪贴板。
2. 所见即所得模式沿用 Crepe 的安全剪贴板能力，禁用 ImageBlock/上传功能；当前没有单独实现 HTML→Markdown 转换器或图片拖放提示层，不能宣称这些细节已经逐项定制。
3. 图片和文件不会由应用上传或写成项目附件；需要强制纯文本时可先切换源码模式。

### 11.8 超大轮次安全模式

1. 单轮 UTF-8 原文达到 2 MiB 时直接使用“安全只读预览 + CodeMirror 源码”，禁用所见即所得；当前未实现 50,000 节点和 500 毫秒两种额外判据，也不提供主动强开 WYSIWYG。
2. 单轮业务硬上限为 10 MiB UTF-8；导入在完整读取前先检查文件和声明长度，超限时不修改现有数据并提示拆分，不静默截断。
3. 备份恢复遵循归档总量、数据库和字体上限；对未来超限备份拒绝覆盖当前数据并保留原备份。

## 12. 字体执行方案

### 12.1 字体角色

分别配置：

- 界面字体：导航、时间线、按钮、设置和搜索。
- 正文字体：所见即所得、源码编辑、预览和折叠卡片的非代码文本。
- 代码字体：行内代码、围栏代码块和语言标识。

每类独立保存家族、字号、粗细和行高。主题切换不改变字体。

默认值：

| 角色 | 默认家族与回退链                                                | 字号 |                       粗细 |
| ---- | --------------------------------------------------------------- | ---: | -------------------------: |
| 界面 | MiSans → Segoe UI Variable Text → Segoe UI → Microsoft YaHei UI |   14 | 常规（MiSans Normal 文件） |
| 正文 | MiSans → HarmonyOS Sans SC → Microsoft YaHei                    |   16 | 常规（MiSans Normal 文件） |
| 代码 | Sarasa Mono SC → Cascadia Mono → Consolas                       |   14 |                        400 |

说明：

1. MiSans 家族的“常规”档固定绑定 `MiSans-Normal.ttf`（OS/2 字重值同为 400，笔画比 Regular 更清瘦，正文观感更干净）；`MiSans-Regular.ttf` 不打包、不展示，避免同档位出现两个几乎相同的选项。
2. Segoe UI Variable 仅 Windows 11 提供，回退链必须包含 Segoe UI 以覆盖 Windows 10 22H2。
3. 代码区域关闭会影响字符辨识和列对齐的字体连字。

### 12.2 字体来源

1. 核心内置字体：资源白名单中的字体。
2. Windows 系统字体：由 Rust 枚举，按实际可用性展示。
3. 私人字体库：由当前用户显式单个或批量导入，复制到 `data/fonts/imported/<sha256>.<ext>`。
4. 当前工作区的 `开发文件夹/素材/字体候选库/` 是候选素材库：只有 12.4 白名单明确选入的文件进入核心资源，其余一律不打包、不使用通配符复制，仅可由用户主动导入为私人字体。

支持 `.ttf`、`.otf`、`.woff`、`.woff2` 和可变字体。首版不直接导入 `.ttc` 字体集合；已由 Windows 安装的 TTC 字体可以作为系统字体使用。

### 12.3 常用粗细

字号控件同时提供滑杆、加减按钮和整数输入，并使用 Windows 缩放下的逻辑像素：

| 角色   | 可选范围 | 默认值 |
| ------ | -------: | -----: |
| 界面   |   12～22 |     14 |
| 正文   |   12～32 |     16 |
| 代码块 |   11～28 |     14 |

Markdown 标题按正文基础字号使用固定比例缩放；行内代码使用代码字体与粗细，但字号跟随所在正文。高级设置提供正文行高 1.20～2.20、代码行高 1.20～2.00，步长 0.05，默认分别为 1.65 和 1.55。

普通界面只展示真实存在的：

- 常规 400（MiSans 家族使用 Normal 文件，见 12.1）。
- Medium 500。
- SemiBold/DemiBold 600。
- Bold 700。

Thin、ExtraLight、UltraLight、Light、Heavy、ExtraBold、Black 不显示。可变字体仅把 `wght` 映射到上述四档。使用 `font-synthesis: none`，禁止 WebView2 伪造粗体或斜体；字体缺少真实档位时不显示，Markdown 粗体选择最近的真实更重档或安全回退字体。斜体不作为粗细选项，Markdown 斜体优先使用匹配字重的真实 italic face，不存在时才沿回退链寻找。

唯一例外：代码字体缺少真实 Bold 时，允许仅在代码区域对加粗语义使用受控合成粗体，避免行内代码在粗体上下文中失去强调；内置 Sarasa Mono SC 已配真实 Bold，此例外仅服务用户自选的单字重等宽字体。

### 12.4 当前字体素材治理

当前素材基线：13 个顶层字体包、538 个字体文件、约 457.57 MiB。其中 Hubot Sans 和 Mona Sans 共 454 个跨格式/宽度/粗细组合。

执行策略：

1. 源素材不删除，保留回退能力。
2. Hubot Sans 和 Mona Sans 如使用，各只采用一个正式可变 WOFF2。
3. 静态中文字体每个家族最多选用 400、500、600、700 中真实存在的必要文件。
4. 同一 face 不同时打包 TTF、OTF、WOFF、WOFF2。
5. 构建脚本只读取 `font-manifest.json`，白名单外文件一律不复制。
6. 0.1.1 只提供设置页内的显式字体文件选择与批次导入；EXE 相邻 `字体/` 目录扫描和“一键批量导入”仍是未来目标。
7. 未经用户明确选择的候选文件不进入 `data/fonts/imported/`，也不进入任何交付包。

首版冻结的核心内置字体共 4 个家族：

- MiSans（默认界面与正文字体）：`MiSans-Normal.ttf`（常规档，OS/2 字重 400）、`MiSans-Medium.ttf`（500）、`MiSans-Semibold.ttf`（600）、`MiSans-Bold.ttf`（700），取自当前素材目录“MiSans 开发下载字重”。`MiSans-Regular.ttf` 与 `MiSans-Demibold.ttf` 和入选文件档位重复（实测 OS/2 字重相同），不打包。MiSans 许可允许全球免费商用及软件嵌入，条件为在软件中注明使用 MiSans、不修改字体、不单独分发字体文件本身；“关于 / 字体许可”页必须包含该注明及协议文本。
- HarmonyOS Sans SC（内置备选中文字体）：`HarmonyOS_Sans_SC_Regular.ttf`（400）、`HarmonyOS_Sans_SC_Medium.ttf`（500）、`HarmonyOS_Sans_SC_Bold.ttf`（700），随附当前目录中的许可（允许随软件再分发，不得修改、不得单独分发）。
- Mona Sans：`Mona-Sans.woff2` 单个变量字体，仅向普通界面暴露 400/500/600/700，用作可选西文字体，随附 `LICENSE.txt`。
- Sarasa Mono SC 1.0.37：`sarasa-mono-sc-regular.ttf`（400）与 `sarasa-mono-sc-bold.ttf`（700），作为默认中英文代码字体，确保一个 CJK 全角单元等于两个 ASCII 半角单元，真实 Bold 保证行内代码在粗体上下文可见加粗；S0 从官方单家族 TTF 发布包取得、记录 SHA-256，并随附 SIL OFL 1.1。构建过程不得联网临时下载。
- Segoe UI / Microsoft YaHei UI / Cascadia Mono / Consolas 属于 Windows 系统字体回退，不复制进核心资源。

苹方、方正悠黑、汉仪旗黑、小米兰亭 Pro、OPPO Sans、OpenAI Sans、Anthropic Sans 等当前本地候选只允许通过上述用户主动批量导入或后来单独导入。界面来源明确显示为“用户导入”，不得冒充“软件内置”；未来分享时默认剔除并重新审计。

`GoogleSans+思源黑体台标.ttf` 因文件名、内部家族和修改来源不一致，首版隔离，不自动加载，需人工确认后才能作为私人导入字体。

### 12.5 字体导入

1. Rust 使用 `ttf-parser + wuff` 校验文件 magic、OpenType 表结构、face、weight、style、stretch 和变量轴，覆盖 ttf/otf/woff/woff2，不自研字体解析器。
2. 计算 SHA-256 去重并生成不冲突的内部族名。
3. 不直接信任文件名或字体内部 CSS 名称。
4. 首版单字体文件硬上限 50 MiB，私人字体库硬上限 500 MiB；超限文件不复制，提示用户精简，确保同版本生成的备份始终可恢复。
5. 字体解析放后台线程，不经 base64 或大块 IPC 传输。
6. 只有当前选中或字体列表可见项才注册和解码。
7. 删除正在使用的字体前先选择回退；文件损坏时保留设置并标记“不可用”。
8. 复制任何非核心字体前展示来源与许可提示，用户确认其有权在本机个人使用；确认记录只保存文件哈希和时间，不替代字体授权本身。
9. 前端通过只读 `vprfont://<font-id>` 加载 registry 中的用户字体，通过 `vprasset://` 加载白名单核心资源。Rust 规范化并校验标识、路径与固定 MIME，绝不把整个 `data/` 暴露给 WebView。

### 12.6 字体设置体验

1. 字体选择器支持搜索、收藏、最近使用和按来源筛选。默认排序固定为“推荐 → 收藏 → 最近使用 → 用户导入 → 系统字体 → 其余内置”，各组内按显示名称自然排序；代码字体页把真实等宽字体提前到每组顶部。
2. 可见字体项用自身字体显示短样例，列表虚拟化并懒加载。
3. 固定预览覆盖中文、英文、数字、标点、Emoji、标题、粗斜体、链接、列表、引用、表格和代码。
4. 设置期间工作区实时临时预览；“完成”保存，“取消”或 `Esc` 恢复快照。
5. 支持调整备用字体顺序，最终 Windows/Emoji 回退不可移除。
6. 字体加载完成后再切换 CSS token 并重新测量时间线，避免闪白和跳位。
7. 提供“恢复当前分类默认值”和“全部恢复默认值”；恢复也先作为临时预览，点击完成才持久化。
8. 大字体解析或解码超过 300 毫秒时显示轻量加载状态，但不阻塞设置页其他操作。
9. “关于 / 字体许可”列出每个核心内置字体的家族、版权方、协议和随附声明，并把私人字体明确标为“由当前用户本机提供”。

### 12.7 字体渲染验收

在 100%、125%、150%、200%、250% 缩放检查：

```text
中文字体 ABC xyz 0123456789，。！？“”《》
Il1O0 AVATAR 龘𠮷 😀
```

必须验证真实 400/500/600/700 文件命中、无大面积方框、无裁切、光标和选区位置正确、代码等宽对齐、切换后滚动锚点不变。

## 13. 主题、设计令牌与动画

### 13.1 首版主题

至少提供：

1. 明亮中性。
2. 暖白米色。
3. 薄荷浅绿。
4. 淡紫或天空蓝。
5. 石墨深色。

默认主题按变更记录 1.1 固定为“晴空蓝白”（内部标识 `neutral`），并提供珊瑚暖杏、湖水薄荷、莓果淡紫、曜石深灰与“跟随系统”选项。选择“跟随系统”时：Windows 为浅色使用明亮中性，深色使用石墨深色；用户手动选定某套主题后即退出跟随模式，该选择持久化。系统深浅切换只在跟随模式下生效。

主题使用统一 CSS 设计令牌：背景层级、文字层级、边框、强调色、危险色、成功色、选区、焦点、搜索高亮、代码背景和滚动条。禁止组件写死颜色。

### 13.2 排版、信息层级与间距

界面信息层级是硬性验收项：任何页面都必须能一眼分出“标题、内容、辅助信息”，禁止所有文字接近同一大小、同一粗细的扁平排版。

1. 界面文字固定四级层级令牌（以界面基础字号 14 为基准，随用户调整等比缩放，四舍五入到整数像素）：

   | 层级       | 用途                                          |                                字号 |     字重 | 颜色令牌 |
   | ---------- | --------------------------------------------- | ----------------------------------: | -------: | -------- |
   | 页面级标题 | 设置页标题、当前项目名、空状态主句            |            基准 × 1.45（默认约 20） |      600 | 主文字   |
   | 区块标题   | 设置分组、详情头部、面板标题、“当前：第 N 轮” |            基准 × 1.15（默认约 16） |      600 | 主文字   |
   | 正文/控件  | 列表项、按钮、输入框、菜单                    |               基准 × 1.0（默认 14） | 400～500 | 主文字   |
   | 辅助说明   | 时间戳、字数、来源标签、次要提示              | 基准 × 0.86（默认约 12，不低于 12） |      400 | 次级文字 |

2. 相邻层级之间至少满足“字号差 ≥ 2 逻辑像素”或“字重差 ≥ 100”其中一项，并配合颜色层级；不允许只靠颜色深浅区分主次。
3. 关键强调点默认加粗：项目列表中的项目名（500）、轮次徽标数字（600）、“当前：第 N 轮 / 共 M 轮”（600）、对话框标题（600）、主按钮文字（500）。时间戳、辅助计数一律用辅助层级，不得与标题同重。
4. Markdown 渲染标题按正文基础字号使用固定阶梯：H1 = 1.60×（700）、H2 = 1.40×（600）、H3 = 1.22×（600）、H4 = 1.08×（600）、H5 = 1.0×（600）、H6 = 0.92×（600 + 次级颜色）；H1/H2 下沿可加细分隔线。折叠卡片内标题按同比例缩小但保持层级可辨。最大标题在窄窗口不得撑破布局。
5. 中文界面正文默认行高约 1.65，代码约 1.55；标题行高 1.25～1.4，标题上方间距大于下方（约 1.6 : 1），让标题在视觉上归属其内容块。
6. 卡片、面板和按钮采用一致圆角、间距与阴影级别。
7. 字体大小改变时控件允许增高或省略文字，不能覆盖相邻控件；四级层级的相对关系在任何用户字号设置下保持不变。
8. UI 巡检时对照本节表格逐页核对；发现“扁平、层级不分、全部同灰同小”的页面按 P1 视觉缺陷处理。

### 13.3 动画

1. 常规切换 120～200 毫秒。
2. 不对持续滚轮做自定义惯性。
3. 动画不得延迟输入、保存、复制、删除、搜索或焦点。
4. 遵循 Windows 减少动画设置。

## 14. 搜索执行方案

### 14.1 查询语义

1. 索引项目名称、正式轮次 Markdown 原文和非空草稿，包含代码块。
2. 中文连续子串匹配，英文忽略大小写。
3. 首版不向用户开放正则和 FTS 运算符。
4. 3 个及以上 Unicode 标量值防抖 120 毫秒；1～2 个标量值走参数化 `LIKE` 并防抖 500 毫秒。单次返回有界结果，0.1.1 不提供继续加载分页。
5. 查询带递增 request ID，前端丢弃迟到结果。

### 14.2 搜索模式

打开全局搜索前保存当前项目、轮次、编辑模式、源码选区和详情开关。当前缓冲先同步保存；保存失败时停止搜索并持续提示，不把尚未落库内容伪装成数据库命中。

结果显示项目、轮次/草稿、纯文本上下文、匹配高亮和修改时间。单击或键盘确认结果会直接切换项目并定位轮次；关闭未发生状态变化的搜索不会递增编辑器 epoch，因此不清空编辑器撤销历史。返回原点会恢复已保存的项目、轮次、模式、源码选区和详情状态；目标失效时跳过而不定位到错误轮次。独立“搜索预览层”和双击提交尚未实现。

命中位置以 Markdown 原文 offset 保存。首版统一以源码模式打开命中轮次并精确选中命中范围（可靠且实现简单）；用户随后可自行切回所见即所得。不做“跳到近似段落”的模糊定位。

`Ctrl+F` 只查当前编辑器；`Ctrl+Shift+F` 打开跨项目全局搜索；编辑器内 `Ctrl+K` 保留给插入或编辑链接。

## 15. 撤销、回收站与排序

### 15.1 文字撤销

文字撤销由当前编辑器自带的历史机制负责：所见即所得使用 Milkdown History，源码模式使用 CodeMirror 历史，二者不做跨模式合并。

1. `Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z` 在编辑器有焦点时只作用于当前编辑器的历史。
2. 切换编辑模式会重建编辑器并清空撤销历史；发生此情况时显示一次轻量提示“已切换模式，此前的编辑不能再撤销”，同一会话不重复打扰。
3. 历史按轮次隔离，切换轮次不串历史；重启后不要求保留。
4. 模式切换本身不产生可撤销事务；迟到的旧编辑器实例响应不得覆盖新会话内容。

### 15.2 结构撤销

1. 项目、轮次、草稿清空和排序生成反向操作记录。
2. 结构撤销通常按项目隔离；删除项目同时压入全局结构栈。8 秒内焦点不在文本编辑器时，`Ctrl+Z`、提示条或最近删除入口都能恢复刚删除项目。
3. 排序可用拖动手柄或 `Alt+Shift+↑/↓`，完成后显示 8 秒撤销提示。
4. 拖动到边缘时自动滚动；按 `Esc` 或取消拖动恢复原顺序。
5. 清空草稿后如果用户已经输入新内容，再撤销时默认把旧草稿恢复为紧邻的正式“恢复副本”，并允许用户改选“用旧内容替换当前草稿”；不得静默覆盖新输入。

### 15.3 回收站

1. 软删除不自动过期，避免启动流程执行未经确认的不可逆删除。
2. 展示对象类型、名称/摘要、原项目和删除时间。
3. 恢复轮次时原项目存在则恢复原位置；项目已删除时先恢复项目或恢复为新项目。
4. 永久删除和清空回收站必须确认并显示目标数量。
5. 删除、恢复和清理与搜索索引在同一事务中更新。

| 主要区域循环焦点      | `F6` / `Shift+F6`                  | 顶部操作栏→项目→时间线→详情                    |
| 打开详情              | `Enter` / `Space`                  | 轮次卡聚焦；Space 阻止页面滚动                 |
| 关闭详情/菜单/搜索    | `Esc`                              | 返回原焦点                                     |

中文 IME 组合输入期间不触发会切换内容或销毁编辑器的快捷键。`Esc` 优先交给 IME；组合结束后依次关闭最内层链接/菜单/当前查找，再退出全局搜索，最后才收起详情。操作在当前状态不可用时无副作用，只显示一次轻量说明。

Milkdown 与 CodeMirror 对表中快捷键的默认行为必须显式覆盖：`Enter` 固定为当前文本换行，`Ctrl+Enter` 固定为新段落，单独按下并松开 `Ctrl` 才执行“完成并新建下一轮”。`Ctrl` 与其他键组合时不得误触发；IME 组合期间不执行全局动作。

窄窗详情抽屉、设置、确认框和冲突恢复比较层打开时启用焦点陷阱：`Tab/Shift+Tab` 只在最上层区域循环，背景使用 `inert` 并暂时移出可访问树和 Tab 顺序；打开时焦点进入标题或首个安全操作，关闭后恢复到触发控件。独立数据库恢复页没有可交互背景，危险操作永远不获得默认焦点。

## 17. 操作反馈与边界状态

### 17.1 状态反馈

1. 自动保存正常时仅在详情区显示“正在保存 / 已保存 HH:mm:ss”，不弹通知。
2. 复制成功显示 1.5 秒轻提示；复制失败保留内容并给出“重试”入口。
3. 删除、清空草稿和排序完成后显示 8 秒可撤销提示，同类操作可合并计数。
4. 需要等待的操作超过 300 毫秒才显示加载状态，避免界面闪烁。
5. 导入、导出、备份和恢复显示 busy 状态、原生文件选择和最终成功/失败提示；0.1.1 尚无细粒度百分比进度事件。
6. 所有错误使用简体中文，同时提供可复制的技术详情；默认不暴露无意义堆栈。

### 17.2 空状态

| 场景             | 显示内容                 | 主操作              |
| ---------------- | ------------------------ | ------------------- |
| 没有项目         | 简短说明数据仅保存在本机 | 新建项目            |
| 项目没有正式轮次 | 显示当前草稿编辑器       | 开始输入            |
| 搜索无结果       | 展示当前关键词及搜索范围 | 清空搜索            |
| 回收站为空       | 不渲染占位列表           | 返回设置            |
| 字体无匹配       | 说明筛选条件             | 清除筛选 / 导入字体 |

### 17.3 关键边界

1. 空白草稿不生成正式轮次；只含空格或换行视为空白。
2. 单轮原文建议软提示阈值为 2 MiB，但不静默截断；达到阈值后仍可保存、导出和切到源码模式。
3. 业务数据库首版支持上限为 8 GiB，达到 7.5 GiB 持续提示备份和清理；达到上限后停止新增内容但继续允许删除、复制、导出与恢复。不得依靠 SQLite 报“磁盘满”才告知。
4. 项目名称去除首尾空白；显示名为空时生成默认名，重名允许，内部 ID 永不重复。
5. 删除当前轮后选择同位置的下一轮；没有下一轮则选择上一轮；都没有则回到草稿。
6. 源码无法被所见即所得编辑器可靠解析时，自动进入只读安全预览 + 可编辑源码模式，原文不得被覆盖。
7. 字体、主题或窗口尺寸变化后，以当前轮 ID 和文本锚点恢复位置，不能仅依赖像素偏移。
8. 应用退出前同步 flush 尚未提交的草稿；若失败则阻止退出并提供继续编辑、重试、复制缓冲或导出应急副本。当前关闭保护中不提供数据目录迁移入口。

### 17.4 关键错误与恢复界面

| 场景                               | 主文案与状态                                         | 可执行操作                                   | 可否继续编辑 / 初始焦点         |

## 18. 导入、导出、备份与恢复

### 18.1 可读 Markdown 导出

1. 单项目导出为 UTF-8 `.md`，带 BOM 与否由实现统一固定，首版固定为无 BOM。
2. 文件名使用清理后的项目名和导出时间；非法 Windows 文件名字符替换为全角或下划线。
3. 文件开头包含项目标题和导出时间；各轮以 `## 第 N 轮` 与保存时间分隔（备注非空时标题写作 `## 第 N 轮 · 备注内容`），正文保持 Markdown 原文。
4. 非空草稿放在末尾并标记 `## 当前草稿`；导出前明确显示是否包含草稿，默认包含。
5. 全部项目导出到用户选择位置下的新时间戳子目录，每个项目一个 `.md`，另生成 `index.md`，不覆盖同名旧目录。
6. 图片只保留原 Markdown 引用；字体文件、回收站和应用设置不进入可读导出。
7. 单文件导出先写入目标目录中的临时文件，成功关闭后再替换；覆盖已有文件必须经过系统保存对话框确认，失败时保留原文件。
8. 0.1.1 单项目始终导出一个带版本化结构标记、正文长度和 SHA-256 的 `.md`；全部项目导出为每项目一个文件加 `index.md`。尚未实现因跨边界结构自动改为逐轮目录的分支。

可读导出在文件开头加入 `vpr-export:v1` 不可见注释，每个边界使用本次随机 export UUID、轮次 UUID、正文 UTF-8 长度和 SHA-256 标记；普通 Markdown 阅读器会忽略这些注释。重新导入时只有整套标记、长度和哈希全部通过才拆分为多轮，并在入库前移除工具标记；普通外部 `.md` 一律作为新项目中的一个正式轮次加一个空草稿导入，避免把用户自己的 `## 第 N 轮` 标题误判为分隔符。Markdown 导入保留正文，但不能恢复所有应用设置；需要无损迁移时使用项目包。

### 18.2 可再次导入的项目包

项目包扩展名定为 `.vcpproject`，实际为 ZIP 容器，至少包括：

```text
manifest.json        # 格式版本、应用版本、导出时间、校验信息
project.json         # 项目及轮次元数据（含排序、时间与轮次备注）
content/*.md         # 每轮原始 Markdown，文件名使用内部 ID
```

导入必须先在临时目录校验版本、路径、JSON 结构、文件大小与哈希，再用单个事务写入。项目 ID 冲突时生成新 ID；项目名重名不覆盖，显示“（导入）”后缀。任何一步失败都回滚，现有数据不变。

### 18.3 完整备份格式

完整备份扩展名定为 `.vcpbackup`，同样使用 ZIP 容器，内容包括：

```text
manifest.json
database/app.sqlite3
fonts/imported/**
checksums.sha256
```

`manifest.json` 必须记录备份格式版本、数据库 schema 版本、应用版本、创建时间、文件清单和恢复兼容范围。备份通过 SQLite Online Backup API 或等效一致性快照生成，严禁直接复制正在写入的数据库主文件。

数据目录定位文件属于当前 Windows 环境，不写入备份、也不在恢复时覆盖；应用设置本身已经保存在数据库中。

备份前先执行 8.1 的同步 flush（未保存内容全部落库），并在获取数据库快照时冻结字体导入/移除。随后只复制该快照 `font_registry` 中列出的不可变 SHA 文件；完成哈希对账后才发布 manifest，避免数据库登记的字体与备份实际文件不一致。

### 18.4 自动备份策略

1. 以当前 Windows 本地自然日为界：某日首次成功变更后，如该 `YYYY-MM-DD` 尚无自动快照，等待用户空闲 5 秒再生成；不是从上次时间滚动 24 小时。重新输入时降低任务优先级，不能争抢编辑响应。
2. 每日自动快照只包含数据库（经 SQLite 在线备份 API 生成一致性副本后压缩），manifest 标明“不含字体”；恢复该类快照时字体沿用当前数据目录中已有文件，缺失项按 12.5 规则标记不可用。
3. 每个 ISO 周的第一份成功日快照升级为**周快照**：与手动备份一样是包含数据库和 `fonts/imported/` 的自包含 `.vcpbackup` 全量包。保留最近 7 个日快照 + 最近 4 个周快照；时区改变不会重复覆盖已有 ID；手动备份不自动清理。
4. 自动备份目录总量默认上限 2 GiB；接近上限时先清理超出保留策略的最旧自动备份。若 7 日 + 4 周本身已超过上限，保留最新可恢复快照并明确要求用户扩容，不能静默声称完整保留。
5. schema 迁移、完整恢复和数据目录迁移前额外创建恢复点，最近至少保留 3 个。
6. 备份失败不影响正常编辑，但必须在状态区持续显示警告，直至成功或用户处理。

### 18.5 恢复流程

1. 用户选择备份后，先只读检查版本、完整性、哈希、可用空间及所有归档路径。
2. 正常数据库先执行同步 flush，再创建“恢复前”一致性快照。若当前数据库已经损坏而无法逻辑备份，则在关闭连接后至少把 `db/wal/shm` 和字体复制到只读 quarantine 目录并生成哈希；连 quarantine 都失败时不得覆盖。
3. 在当前数据卷的 `recovery/restore-<uuid>/staged/` 完整恢复并执行 `PRAGMA integrity_check`、`foreign_key_check`、schema、FTS 和抽样内容校验；校验通过后写入并 fsync `restore-state.json`（固定相对路径 + 哈希），然后请求用户重启。
4. 下次启动在创建 WebView2 和打开活动数据库之前按状态切换：`prepared` 时把活动数据库/字体移到 `old-<uuid>` 并进入 `old-moved`；随后把 staged 内容移入正式位置并完成完整性、外键、FTS 与字体 registry/file 对账。删除 `restore-state.json` 即提交成功，不另写会产生崩溃歧义的“完成 phase”。
5. 任意一步被强杀后，下次启动依据状态文件与目录实际存在情况幂等继续或反向回滚，绝不留下新旧混合状态。`webview2/`、日志、marker 和定位文件不参与替换。
6. 恢复失败时恢复 old、保留诊断现场；成功后的 `old-*` / `restore-*` 是可清理工作目录，长期恢复依据是 `backups/manual/recovery-before-*.vcpbackup` 和原备份文件。
7. 较新格式备份不能强行降级导入；较旧受支持格式先迁移副本，永不直接修改原备份。

### 18.6 归档安全

1. 解压时拒绝绝对路径、`..`、符号链接和越出临时目录的条目，防止 Zip Slip。
2. 首版硬限制与生成侧统一：manifest 8 MiB、项目包解压后 4 GiB、完整备份解压后 10 GiB、20,000 个条目、数据库条目 8 GiB、单字体 50 MiB、字体总量 500 MiB。导出前也执行相同检查，保证本版本成功生成的包必能由同版本恢复；超限包只拒绝导入，不影响现有数据。
3. 不执行归档内任何脚本、HTML、快捷方式或可执行文件。
4. 导入字体仍走字体验证流程，不能因为来自备份而绕过格式与大小检查。

## 19. 隐私与安全

### 19.1 本地优先边界

1. 不注册、不登录、不接入模型 API，不做遥测、崩溃内容上传或使用统计上报。
2. 核心功能完全离线；依赖、Markdown 引擎、代码高亮和内置字体都随便携包提供。
3. 不读取终端历史、其他应用窗口、项目代码或系统剪贴板；只有用户执行粘贴或复制时处理相关内容。
4. 首版数据库为本地明文 SQLite。界面必须明确说明：任何能读取便携目录的人也能读取提示词；首版不承诺加密。
5. 日志不得包含提示词正文、项目全文、剪贴板内容或字体文件内容，只记录 ID、错误码、耗时和经过清理的路径。

### 19.2 Tauri 权限与 Web 安全

1. Tauri capability 使用最小白名单；文件访问仅覆盖应用数据目录和用户通过文件选择器明确选择的文件。
2. 禁止任意 shell 执行、任意进程启动、开发者工具生产环境默认开启及前端任意文件系统访问。
3. 配置严格 CSP，禁止内联脚本和远程脚本；所有业务资源使用本地协议。
4. 所见即所得和预览中的 HTML 必须经过同一套白名单消毒，不允许 `script`、事件属性、`iframe`、`object`、`embed`、`javascript:` 等可执行内容。
5. 点击外部链接前展示完整域名并要求确认；只允许系统处理 `http`、`https` 和 `mailto`，其余协议默认拒绝。
6. 远程图片默认不请求；用户单次授权只对该图片本次查看有效，不形成后台联网权限。
7. SQLite 查询一律参数化；排序字段、路径和表名使用代码白名单，不能直接拼接用户文本。

### 19.3 数据目录安全

1. 启动时解析并显示当前实际数据目录，路径不可写时进入只读保护状态，不能假装保存成功。
2. 使用独占锁与单实例机制，避免同一数据目录被两个进程同时写入。
3. 数据目录迁移采用“复制 → 校验 → 下次启动前切换 → 保留旧目录”流程，不做先删后移；切换发生在数据库和 WebView2 打开之前。
4. 归档/导入临时内容写入应用专用 `data/temp`；为保证原子发布，导出临时文件位于用户已选择目标的同目录并使用严格 UUID 命名。启动只清理明确属于本应用的名称，不触碰未知文件。
5. 个人自用不等于可忽略授权；任何未来对外分享都必须重新审核字体许可、第三方依赖许可证和代码签名。

## 20. 性能预算与测量方法

### 20.1 基准环境与数据集

基准机以 Windows 10/11、4 核 CPU、8 GiB 内存、SSD、1920×1080、125% 缩放为最低测量档，另在主力机器上复测。固定数据集：

| 编号 | 数据规模                                     | 用途               |
| ---- | -------------------------------------------- | ------------------ |
| D0   | 空数据 / 首次启动                            | 冷启动与初始化     |
| D1   | 20 项目 × 100 轮 × 每轮 100 行               | 常规综合场景       |
| D2   | 单项目 1,000 轮 × 每轮约 100 行              | 时间线压力场景     |
| D3   | 单轮 2 MiB Markdown，含长代码块和表格        | 编辑器边界场景     |
| D4   | 单项目 1,000 轮，其中 100 个长卡片并关闭折叠 | 动态大卡片压力场景 |
| F1   | 500 个已发现或导入字体文件                   | 字体列表压力场景   |

性能测试使用发布构建。普通冷/热启动各至少 20 次；输入、保存、导航、搜索和详情操作各采集至少 100 个样本；滚动连续采集至少 60 秒。报告同时记录中位数、P95、最差值和原始 trace。迁移和备份恢复切换作为维护启动单列，不混入普通启动 SLO，也不能只凭主观“感觉流畅”验收。

0.1.1 最终个人打包门禁的浏览器壳方向性数据为：D1 100 KiB 保存 392 ms；D3 2 MiB 加载 1,774 ms、保存 1,437 ms；D2 1,000×100 加载 937 ms、尾部定位 79 ms、DOM 卡片 6→5。最终 ZIP 已做原生 fresh-data 与 0.1.0 数据副本启动/安全关闭冒烟；这些证据不替代上段规定的跨机器 20 次启动、100 样本和 60 秒滚动完整报告。

### 20.2 首版硬指标

| 指标             | 验收目标                                                                                                                           |

### 20.3 性能实施约束

1. 时间线必须虚拟化，只渲染可见卡片及小幅 overscan；卡片不得实例化编辑器。
2. 同一时刻最多存在一个可编辑 Milkdown 实例和一个按需 CodeMirror 实例；切换时销毁或休眠另一实例。
3. Markdown 解析、代码高亮、搜索和字体元数据读取使用分片、worker 或 Rust 后端，禁止阻塞输入线程。
4. 代码高亮按语言和可见区域懒加载；未知语言不加载额外语法包。
5. 字体列表、搜索结果和项目列表在数量较大时同样虚拟化；字体预览仅对可见项加载。
6. 路由切换、主题切换和字体切换后检查监听器、编辑器实例与对象 URL 是否释放。
7. 发布门禁保存启动、滚动、搜索、输入与内存报告；相对上一个候选版回退超过 20% 必须解释或修复。
8. 启动只取项目摘要、当前项目轮次摘要和选中轮正文；0.1.1 的 `list_rounds` 一次返回当前项目全部轮次摘要及每轮最多 8192 UTF-16 单元预览，完整正文只按选中/操作需要读取。后端 keyset 分页和 32 MiB 正文 LRU 是未来大规模优化目标。
9. D2 使用默认五行折叠测试；D4 单独验证“不折叠”大卡片，二者不得互相替代。

## 22. 分阶段实施与阶段门

每一阶段都必须形成可运行构建、自动化结果和人工验收记录；阶段门未通过时不把未稳定能力继续叠加到主分支。

0.1.1 当前状态：S0～S3、S5 的本机可自动化范围已完成；S4 的真实 DPI/IME、S6 的完整跨机性能/长期故障边界、S7 的 Win10/另一台 Win11 与 WebView2 缺失外部验收尚未全部关闭。个人自用成品可交付，正式公开发布仍受这些阶段门约束。

### S0：技术尖峰与开发骨架

交付：Tauri 2 + React + Rust 骨架、日志与错误边界、CI 本地脚本、临时设计令牌、测试数据生成器。

同时把 `完整需求.txt` 的每个编号固化为 `REQ-章节.小节.条目`，生成 `需求和方案文件夹/需求追踪表.csv`（原文位置、实现章节、测试 ID、状态、备注）；逐条矩阵完成前不得开始功能编码。

优先验证四个最大风险：

1. Milkdown 对需求语料的 Markdown 往返保真。
2. Milkdown/CodeMirror 与微软拼音组合输入、撤销及模式切换。
3. React Virtuoso 在可变字体、可变行高和 1,000 轮下的锚点稳定性。
4. Windows 系统字体枚举、内置字体与私有导入字体的真实字重加载。

阶段门：四个实验均有可复现样例；若 Milkdown 无法满足保真门槛，先替换编辑内核再进入 S1，不能把内容损坏留到后期补救。

### S1：便携外壳与数据内核

交付：单实例、数据目录选择、SQLite schema/migration、项目与轮次仓储、自动保存状态机、崩溃恢复、窗口状态。

阶段门：APP-01～04、PRJ-01、RND-01～05 通过；可反复强制结束进程而不损坏数据库。

### S2：项目、草稿与时间线主流程

交付：项目管理、草稿到正式轮次、复制、软删除、排序、结构撤销、三栏/抽屉布局、序号、时间、轮次备注与字数统计、虚拟列表和滚动导航。

S2 通过后额外打包一个**过渡可用便携版**交付用户日常试用：编辑暂为源码模式 + 只读安全预览（尚无所见即所得与字体设置页），数据格式与正式版一致，后续版本可直接继续使用同一数据目录。试用反馈作为 S3、S4 的输入。

### S5：导入、导出、备份与恢复

交付：`.md`、`.vcpproject`、`.vcpbackup`、自动保留、迁移前恢复点、完整恢复与回滚。

阶段门：IO 全部通过；使用独立新目录完成至少三次完整恢复，并完成损坏包与 Zip Slip 测试。

### S6：性能、安全与可靠性加固

交付：性能报告、内存与长任务修复、最小权限/CSP 审计、故障注入、无障碍和键盘巡检、错误文案统一。

阶段门：SEC、PERF 通过；P0/P1 缺陷清零；P2 均有记录和处置决定。

### S7：便携版候选与交付

交付：正式 EXE、资源、许可、说明、校验文件、干净机验收记录和可回滚的上一版本。

阶段门：PKG 用例、完整回归、备份恢复演练全部通过；用户在候选版上完成一次真实使用流程后再标记首版完成。

## 23. 关键风险与应对

| 风险                       | 影响                       | 预防与降级                                                         |
| -------------------------- | -------------------------- | ------------------------------------------------------------------ |
| 所见即所得改写 Markdown    | 最高：内容语义或代码被破坏 | S0 金样往返；原文唯一真源；切换不保存；失败立即锁定源码模式        |
| 中文 IME 与编辑器冲突      | 最高：丢字、重复或误快捷键 | 组合事件门控；真实微软拼音测试；IME 期间暂停模式切换和提交         |
| 自动保存与崩溃竞态         | 最高：内容丢失             | 单写入队列、事务、WAL、退出 flush、故障注入、在线备份              |
| 虚拟列表动态高度跳位       | 高：千轮浏览不可用         | 字体就绪后测量；稳定 item key；锚点恢复；固定详情不扩卡片          |

| 字体授权不清               | 高：未来无法分发           | 核心白名单与私人字体库隔离；保留许可证；对外分享前重审             |
| WebView2 缺失或版本异常    | 中：EXE 无法打开           | 发布前检查主力机器；启动错误提供中文说明；首版不静默联网下载运行时 |
| 便携目录不可写/被同步占用  | 高：无法保存或锁冲突       | 启动写测试、显式数据目录选择、只读保护、单实例、重试与应急导出     |
| 备份看似成功但不可恢复     | 最高：灾难时失效           | 一致性快照、哈希、定期自动恢复测试、恢复前快照与原子切换           |
| FTS 与主数据不同步         | 中：漏搜或定位错误         | 同事务维护索引；启动自检；提供安全重建索引                         |
| 代码高亮包过大             | 中：包体与解析变慢         | 只内置常见语言，其他纯文本；按语言懒加载                           |
| 无代码签名触发 SmartScreen | 中：首次运行有系统警告     | 个人自用版在交付说明中明确；未来公开分发再配置可信代码签名         |

## 25. 构建、版本与交付物

### 25.1 构建约束

1. `scripts/package-portable.ps1` 是统一打包入口：默认正式模式要求干净 Git 来源并执行 release 需求门禁；显式 `-PersonalUse` 模式允许从已完整验证的当前工作树生成当前用户成品，但必须保留所有外部 pending。两种模式都依次执行 frozen install、字体/schema/需求追踪、格式/lint/类型、Vitest、Playwright、Rust fmt/Clippy/tests 和 Windows x64 Tauri Release 构建。
2. Rust 发布构建启用合理的尺寸优化、LTO 和 panic 策略，但不得牺牲可诊断性；调试符号单独归档，不放入用户包。
3. 生产配置关闭开发者工具和 source map 对外暴露，生成第三方依赖许可证清单。
4. 构建脚本先依据字体白名单复制资源，再校验实际包内字体；发现未授权或极端字重文件即失败。
5. `--no-bundle` 只生成二进制，不负责组装外部资源。唯一的 `scripts/package-portable.ps1` 显式复制目标 EXE、白名单 `resources/`、`LICENSES/` 与 README；发布 ZIP 不预建 `data/`，由首启按第 4.2 节原子初始化；不制作 MSI/NSIS。
6. 正式发布从干净工作区和可追溯 commit 执行；个人自用通道在 manifest 标记 `verified-working-tree`，不得声称正式来源。两者都验证架构与版本一致；可用时以 `dumpbin /dependents` 生成脱敏依赖清单，未找到工具时明确警告而不伪造结果。
7. `checksums.sha256` 覆盖不可变 EXE、resources、LICENSES、README 及个人包的 `BUILD-STATUS.md`，排除可写 `data/` 与校验文件自身；ZIP 整体 SHA-256 写在 ZIP 外侧同名 `.sha256` 文件中。
8. 每个候选版的版本号同时写入 EXE、关于页、备份 manifest 和发布说明；包装结束后比较产物树，并对最终 ZIP 再次解压复验。个人自用包必须额外包含被 checksums 覆盖的 `BUILD-STATUS.md`。
9. `verify-portable.ps1` 默认从 ZIP 是否含 `BUILD-STATUS.md` 自动识别正式/个人成品，同时支持显式类型；版本从包内字体 manifest 推导，因此能复验历史 0.1.0。
10. `smoke-portable.ps1` 只在隔离数据副本上启动最终 ZIP；`install-personal-build.ps1` 要求应用已退出，先逐文件哈希备份真实 data，再移动旧不可变文件和原数据，失败自动回滚。

### 25.2 版本策略

首版采用 `0.1.0` 起步的语义化版本：修复增加 patch，兼容功能增加 minor，备份格式或行为存在不兼容变化才增加 major。数据库 schema 和备份格式分别维护独立整数版本，不与应用版本混用。

### 25.3 便携交付目录

以下为首次成功运行后的完整目录；交付 ZIP 中尚不存在虚线语义上的 `data/` 分支：

```text
提示词记录工具-<version>-portable/
├─ 提示词记录工具.exe
├─ resources/
│  ├─ fonts/core/
│  └─ font-manifest.json
├─ README-使用说明.md
├─ BUILD-STATUS.md               # 个人自用包
├─ LICENSES/
│  ├─ third-party-licenses.txt
│  └─ fonts/
├─ checksums.sha256
└─ data/                         # 首次启动创建或补齐
   ├─ .vpr-data-root.json
   ├─ .vpr-clean-shutdown
   ├─ instance.lock
   ├─ database/
   ├─ backups/
   │  ├─ auto/
   │  └─ manual/
   ├─ recovery/
   ├─ fonts/imported/

```

此目录与第 4.2 节是同一份规范；实现脚本不得维护第三个不同版本。

个人交付包只带第 12.4 节冻结的核心字体，不自动携带私人字体。当前 `开发文件夹/素材/字体候选库/` 源素材目录不在开发阶段删除；用户可在首次运行时一键批量审阅并导入，随后字体位于 `data/fonts/imported/` 并随完整备份迁移。

### 25.4 每次候选版交付清单

- 便携 ZIP 与解压后的主 EXE。
- SHA-256 校验值和版本说明。
- 本版本变更、已知限制与数据兼容说明。
- 自动化测试汇总、当前本机性能基准；两套 Windows 冒烟只有实际完成后才能写为通过，未完成时必须列为 external pending。
- 字体实际打包清单、第三方依赖许可清单。
- 数据目录、手动备份、完整恢复和升级回退说明。

首个个人自用版本默认不做代码签名，因此 Windows 可能显示未知发布者提示；这不是程序内部错误。若未来交给他人使用，应把代码签名和公开分发检查作为新的发布阶段，而不是直接复制当前包。

## 26. 审阅结论与变更规则

### 26.1 当前无需继续确认的事项

以下问题已有明确答案或已采用低风险默认值，不阻塞开发：

1. 使用范围：仅当前用户个人使用。
2. 平台与形态：Windows 10/11 x64、免安装便携版、单实例、关闭即退出。
3. 编辑体验：默认所见即所得，可切 Markdown 源码；Markdown 原文是唯一真源。
4. 图片：识别并保留语法，不做粘贴、上传、附件管理；远程图片默认不联网。
5. 折叠：默认 5 个视觉行，可配置 1～20 或不折叠；完整内容在固定详情区打开。
6. 时间线：默认显示显眼序号、完整保存时间能力、项目级滚动记忆与一键顶部。
7. 字体：三类独立配置，仅保留 400/500/600/700；默认界面与正文为 MiSans（常规档用 Normal 文件）；核心授权字体与私人字体库分开。
8. 数据：输入防抖 300 毫秒直接落库（WAL + FULL）、不自动过期的回收站、7 日 + 4 周自动备份（日快照仅数据库、周快照全量）。
9. 安全：不上传、不监听、不扫描；数据库首版不加密。

### 26.2 可在开发中替换、无需阻塞的内容

工作名称、应用图标、浅色主题的具体名称、首批代码高亮语言顺序和少量动画曲线均属于可替换外观项。默认先使用一致、克制的占位方案；它们不得改变数据格式、核心交互或阶段进度。

### 26.3 需求变更流程

1. 审阅意见直接标注“接受 / 修改 / 删除 / 新增”，并说明希望的结果即可，不要求提供技术方案。
2. 影响数据格式、Markdown 保真、备份兼容或主布局的变更，先更新本文档和验收项，再实施代码。
3. 纯视觉微调可进入设计令牌，不随意产生分散的组件特例。
4. 本文档保持“已批准执行”并按实现校准递增文档版本；当前版本为 1.4，后续修改继续保留变更记录和未完成边界。
