# 恢复与迁移说明（适用于 0.1.4）

> 文档更新：2026-07-31。旧版升级到 0.1.4 时数据库 schema 仍为 v2，项目包和完整备份格式仍为 v1。

## 数据安全优先级

1. 保存失败时先保持应用运行，不清空编辑器；使用“复制缓冲”或“导出恢复文件”。
2. 数据库异常时先复制整个 `data/` 作为现场，不删除 `app.sqlite3-wal` / `app.sqlite3-shm`，不用空库覆盖。
3. 只恢复通过格式版本、条目路径、大小、SHA-256、SQLite 完整性、外键、项目/轮次/视图业务语义和 FTS 原文一致性检查的 `.vcpbackup`。
4. 恢复前会创建 `backups/manual/recovery-before-*.vcpbackup`。这是长期保留的恢复点；`recovery/restore-*` 与 `recovery/old-*` 是切换工作目录，成功提交后可由后续启动清理。
5. 设置值损坏时，原 JSON 会先保存为数据库中的 `settings.broken.*`，再使用默认设置继续；未来设置格式版本不会被旧程序降级覆盖。

## 数据根选择与边界

数据根优先级为：显式 `--data-dir` → `VPR_DATA_DIR` → EXE 相邻 `data/` → 当前 EXE 对应的 `%LOCALAPPDATA%\VibePromptRecorder\locators\` 定位文件 → 原生目录选择器。

- 数据根必须带有效 `.vpr-data-root.json`，非空且没有 marker 的目录不会被认领。
- `instance.lock` 防止同一数据目录并发写入；`%LOCALAPPDATA%\VibePromptRecorder\initialization-locks\` 防止候选目录并发首启。
- UNC 和映射网络驱动器不能作为活动数据库目录。OneDrive、Dropbox 等已知同步目录会警告但不自动删除或搬迁数据。
- 第二实例携带新的 `--data-dir` 不会切换已运行实例，程序会明确提示；请先安全关闭旧实例。

## 便携迁移

完全退出应用并确认任务管理器中没有 `提示词记录工具` / `vibe-prompt-recorder` 进程，然后复制含 `data/` 的整个便携目录。不要只复制 EXE，也不要在应用运行时复制活动数据库。

复制完成后：

- 先用包内 `checksums.sha256` 核对 EXE、资源、许可和说明文件；
- 再启动新位置的 EXE；程序旁已有有效 `data/` 时会优先使用它；
- 若只想移动数据而不移动程序，使用程序提示的本地目录选择流程，不手工修改 locator JSON。

## 从旧版升级到 0.1.4

1. 完全关闭旧版本。
2. 复制旧 `data/` 到独立升级备份目录。
3. 用 0.1.4 的 EXE、`resources/`、`LICENSES/`、README、`BUILD-STATUS.md` 和 `checksums.sha256` 替换不可变文件；保留原 `data/`。
4. 首次启动后确认项目、草稿、设置和字体可见，再安全关闭并检查 `.vpr-clean-shutdown`。
5. 如需回退，先关闭应用，再恢复升级前完整目录；不要混用新旧 `resources/` 和校验文件。

本轮不会自动升级或读取任何真实使用目录；应由用户在确认旧版本已完全退出并保留独立数据备份后，再按上述步骤替换不可变文件。

## 完整备份恢复协议

选择 `.vcpbackup` 后，应用会在数据库锁外完成归档路径、大小和哈希校验，在当前数据卷的 `recovery/restore-<uuid>/` 暂存并验证数据库与字体，然后写入 `restore-state.json`。下次启动在打开业务数据库前执行切换：

- `prepared`：旧活动目录仍是权威；中断时可以直接回滚。
- `old-moved`：旧目录已经移到工作区；程序会根据状态和实际目录幂等继续或回滚。
- 新数据库、外键、FTS 和字体对账全部通过后，删除状态文件即提交成功。

0.1.4 在恢复尚处于 `prepared` 且活动数据尚未移动时提供“取消待恢复”。取消会先撤销待恢复状态，再删除暂存目录；清理失败不会把已取消的恢复重新标记为待执行，后续启动会收敛遗留临时目录。

成功后不长期保留 `old-*` / `restore-*` 工作目录；长期回滚依据是 `backups/manual/recovery-before-*.vcpbackup` 和用户自己保留的原备份。失败或中断时不要手工删除状态文件和工作目录，先复制现场。

## 启动或恢复失败

- 启动级数据库、schema 或恢复错误当前会在创建业务窗口前显示原生中文错误并退出，不会创建空库覆盖现场；当前版本没有独立图形恢复页。
- 恢复准备失败时主数据库尚未移动。
- 切换中断时保留 `restore-state.json`、`restore-*`、`old-*` 和日志，下一次启动会尝试收敛；反复失败时先复制整个 `data/`。
