# Vibe Coding 提示词记录工具需求文档

> 文档版本：1.4  
> 修订日期：2026-07-31  
> 适用版本：0.1.4 个人自用便携成品  
> 状态说明：产品需求继续有效；实现证据见 `需求追踪表.csv`，最终验证见 `验收报告-0.1.4.md`。外部环境待验不等于功能缺失，也不得被伪造为通过。

## 一、产品定位

开发一款面向 Windows 的轻量级提示词记录工具，用于按照项目管理用户在 Vibe Coding 过程中的多轮提示词。

软件只记录用户自己编写的提示词，不记录 AI 回答，不接入任何特定模型、终端或编程工具。

首个版本仅供当前用户个人使用，不面向第三方公开发布或商业分发；如果未来需要分享给他人，必须重新审查字体授权、代码签名和发布方式。

产品核心目标：

* 启动迅速
* 操作流畅
* 界面美观
* 使用简单
* 数据安全
* 长期记录不混乱

---

## 二、界面、主题与字体

### 2.1 界面与主题

1. 界面整体美观、优雅、简洁。
2. 支持深色模式和多种彩色浅色主题。
3. 主题配色必须全局生效。
4. 支持一键切换主题。
5. 支持流畅但不过度的界面动画。
6. 主题选择和界面状态应自动保存。
7. 界面默认使用简体中文。
8. 界面信息层级必须分明：页面标题、区块标题、正文、辅助说明在字号和字重上拉开明显差距，该加粗的加粗、该放大的放大；不允许所有文字接近同一大小、同一粗细的扁平效果。Markdown 渲染的各级标题也必须有清晰的大小阶梯。

### 2.2 字体作用范围

1. 在“设置 → 外观 → 字体”中提供统一的字体设置页面。
2. 字体设置至少分为三个互不干扰的作用范围：

   * 界面字体：项目列表、时间线、菜单、按钮、弹窗、搜索结果和状态文字。
   * 正文字体：Markdown 所见即所得编辑、源码编辑、折叠预览及详情阅读中的非代码内容。
   * 代码字体：行内代码、围栏代码块、语言标识和代码复制区域。
3. 每个作用范围都可以独立设置字体家族、字号和基础粗细。
4. 原生 Windows 标题栏等由系统绘制的区域不强制跟随界面字体。
5. 所有主题共用用户选择的字体设置；切换主题只改变配色，不擅自改变字体。
6. 首个版本使用全局字体设置，不按项目分别保存字体方案。

### 2.3 字体来源与自定义导入

1. 字体选择器支持软件内置字体、当前 Windows 已安装字体和用户导入字体。
2. 支持导入常见的 `.ttf`、`.otf`、`.woff`、`.woff2` 字体，并支持具有粗细轴的可变字体。
3. 导入字体时将字体复制到便携版专用数据目录，不依赖原始文件持续存在，也不安装到 Windows 系统字体目录。
4. 使用文件内容哈希和字体内部名称识别重复导入，避免产生多个相同选项。
5. 支持搜索字体名称、收藏常用字体，并优先展示推荐字体、收藏字体、最近使用字体和用户导入字体。
6. 代码字体选择器默认优先展示等宽字体。
7. 用户可以移除已导入字体；正在使用的字体被移除或丢失时，应先切换到可靠的回退字体并保留原设置记录。
8. 字体文件损坏、格式不受支持或无法加载时，使用简体中文说明原因，不能导致设置页、编辑器或软件启动失败。
9. 用户导入字体属于全局外观资源，完整备份应包含其文件和设置；单项目 Markdown 导出不包含字体文件。

### 2.4 字号与常用粗细

1. 字号使用兼容 Windows 显示缩放的逻辑像素，支持滑杆、加减按钮和直接输入整数。
2. 界面字体支持 12～22，默认 14；正文字体支持 12～32，默认 16；代码字体支持 11～28，默认 14。
3. Markdown 标题字号按正文基础字号保持稳定比例，调整正文字号后仍须保持清晰的标题层级。
4. 行内代码使用代码字体家族和粗细，但字号跟随所在正文；独立代码字号主要用于围栏代码块。
5. 普通设置中只保留以下四档常用粗细：

   * 常规 Regular：400。
   * 中等 Medium：500。
   * 半粗 SemiBold / DemiBold：600。
   * 粗体 Bold：700。
6. 不显示 Thin、ExtraLight、UltraLight、Light、Heavy、ExtraBold、Black 等极细、极粗或低频粗细选项。
7. 字体实际缺少某个常用粗细时，不显示该档位，也不能把合成粗体伪装成真实字体文件。
8. 可变字体只在普通界面映射 400、500、600、700 四个常用档位，不显示连续的极端粗细轴。
9. Markdown 粗体使用比正文基础粗细更重的真实可用字重；切换粗细不得改写 Markdown 原文。
10. 实际斜体文件不作为“粗细”选项单独展示，但 Markdown 斜体应优先使用字体自带的真实斜体字形。
11. 正文和代码区域在高级设置中支持调整行高，默认值应优先保证中文阅读舒适度和代码行辨识度。

### 2.5 内置字体资源治理

1. 当前目录中的“字体”文件夹作为内置字体候选素材库，构建时不得不加筛选地全部打包。
2. 每个字体家族优先只保留 Regular 400、Medium 500、SemiBold / DemiBold 600、Bold 700 及对应的必要斜体文件。
3. 静态字体同时存在 TTF、OTF、WOFF、WOFF2 多套重复格式时，最终便携版只选择一套最合适且许可允许的格式。
4. Hubot Sans、Mona Sans 等已提供正式可变字体文件的家族，优先只使用单个可变字体资源，不打包数百个重复的宽窄、粗细和格式组合。
5. Thin、ExtraLight、UltraLight、Light、Heavy、ExtraBold、Black 等源文件不进入最终便携版资源，也不出现在字体选择器中。
6. 开发素材目录中的原始字体暂时保留用于核对和回退；在建立最终字体白名单前不直接删除源文件。
7. 随软件分发的字体必须具有清晰、可验证的嵌入和再分发授权，并按许可要求保留协议及字体使用声明。
8. 仅仅出现在“字体”目录中不代表已经获得再分发授权；授权不明确的字体不得进入可公开分享的便携版，但仍可由拥有合法使用权的用户作为本机自定义字体导入。
9. 构建前生成明确的字体清单，记录字体家族、实际文件、粗细映射、格式、体积、授权状态和所需声明。

### 2.6 缺字回退与渲染质量

1. 默认启用自动缺字回退，依次使用用户主字体、用户备用字体、内置中文或等宽兜底字体、Windows 系统字体和系统 Emoji 字体。
2. 用户可以在高级设置中调整备用字体顺序，但最终系统兜底项不能移除。
3. 中文、英文、数字、常见标点、Emoji 和代码符号必须能够稳定混排，不能因主字体缺字而大面积显示方框。
4. 代码区域优先回退到等宽字体，保证空格、Tab、缩进和列对齐。
5. 所见即所得编辑器、源码编辑器、Markdown 预览、折叠卡片和复制前的可视内容必须使用同一套字体映射规则。
6. 字体必须以真实文本方式由 Windows / WebView2 字体引擎渲染，不得为了视觉效果将正文栅格化成图片或 Canvas 文本。
7. 字体加载完成后再计算折叠预览高度和虚拟列表尺寸，避免字体切换造成文字截断、轮次跳位或滚动位置丢失。
8. 切换字体、字号和粗细不得中断中文输入、丢失光标、选区、当前轮次或未保存内容。
9. 字体渲染必须在 Windows 100%、125%、150%、200% 和 250% 显示缩放下进行验收。

### 2.7 实时预览、保存与恢复

1. 字体设置页提供固定实时预览区，至少展示中英文、数字、标点、Emoji、标题、正文、粗体、斜体、链接、列表、引用、表格、行内代码和多行代码块。
2. 调整字体、字号、粗细或回退顺序时，预览区和当前工作区立即同步临时效果，无需反复点击保存。
3. 点击“完成”后保存字体设置；点击“取消”或按 `Esc` 恢复打开设置页前的设置。
4. 字体设置在软件重启后自动恢复，并提供“恢复当前分类默认值”和“全部恢复默认值”。
5. 加载大型中文字体时显示轻量状态，只按需加载当前使用或正在预览的字体，不能一次性载入全部内置字体阻塞启动。
6. 字体改变后界面、Markdown 层级、按钮和时间线仍须保持完整可用，不能出现文字永久遮挡或控件无法点击。
7. 字体列表中的可见选项使用自身字体显示简短示例，但必须懒加载，不能为不可见的数百个字体同时创建预览。
8. 默认界面字体与正文字体使用内置的 MiSans，其中“常规”档固定使用 MiSans Normal 字重文件，Windows 中文系统字体作为回退；默认代码字体从授权明确的内置中英文等宽字体中选择，系统等宽字体作为代码回退。
9. 软件“关于 / 字体许可”页面列出所有内置字体、版权方、授权协议和必要声明。

## 三、性能要求

1. 软件启动速度快。
2. 界面切换和输入过程流畅。
3. 长提示词和大量历史记录下仍能正常使用。
4. 软件保持轻量，不因非必要功能增加资源占用。
5. 关闭窗口后默认直接退出，不强制常驻后台。
6. 大量轮次采用虚拟列表或等效方案，只渲染当前可见内容，不能一次性渲染全部历史轮次。
7. 鼠标滚轮、键盘导航、轮次切换、折叠和详情打开过程不得出现明显卡顿、跳位、闪烁或白屏。
8. Markdown 解析、代码高亮和自动保存不能阻塞中文输入、光标移动与列表滚动。
9. 同一时刻只激活详情区域中的一个所见即所得编辑器；历史轮次卡片使用轻量只读渲染，不能为每个轮次同时创建编辑器。
10. 首版至少使用“单项目 1,000 轮、每轮约 100 行 Markdown”的压力数据验证连续滚动、方向键切换、详情打开和回到顶部操作。

## 四、项目管理

1. 支持新建项目。
2. 新建项目时可以不填写名称。
3. 未填写名称时，自动生成连续项目名称，例如：

   * Vibe Coding 项目-1
   * Vibe Coding 项目-2
   * Vibe Coding 项目-3
4. 支持修改项目名称。
5. 支持删除项目。
6. 支持项目置顶。
7. 项目默认按照最近使用时间排序。
8. 支持在多个项目之间快速切换。
9. 每个项目独立保存自己的提示词记录。

---

## 五、多轮提示词管理

1. 每个项目支持保存多轮提示词。
2. 每一轮提示词必须独立保存，不能与其他轮次合并。
3. 支持直接在项目中编写提示词。
4. 支持一键将当前内容保存为独立轮次，并开始下一轮。
5. 支持使用快捷键快速创建下一轮。
6. 支持随时编辑任意一轮提示词。
7. 支持删除任意一轮提示词。
8. 支持调整提示词轮次顺序。
9. 支持单独复制任意一轮提示词。
10. 支持一键复制当前项目的全部提示词。
11. 复制操作不能自动创建下一轮。
12. 提示词内容输入后自动保存。
13. 自动保存的耐久性要求：停止输入约 300 毫秒内将当前内容完整写入本地数据库并确保落盘（超大内容可放宽到约 1 秒）。正常关闭和可正常处理的异常退出不得丢失任何内容；程序崩溃、系统强制终止或断电的最坏情况，只允许丢失最近约 1 秒内的输入。保存失败时必须立即持续显示“内容尚未安全保存”警告，不得把未落盘内容标成已保存。
14. 完全不记录 AI 的回答。

## 六、Markdown 编辑、渲染与轮次浏览

### 6.1 Markdown 支持范围

1. 完整支持 CommonMark 和 GitHub Flavored Markdown（GFM）常用语法。
2. 支持标题、段落、软换行和硬换行、粗体、斜体、粗斜体、删除线、引用、分隔线、链接、自动链接和转义字符。
3. 支持有序列表、无序列表、嵌套列表、任务列表和表格。
4. 支持行内代码、缩进代码块和围栏代码块。
5. 首个版本不包含数学公式、Mermaid 图表、脚注、自动目录、YAML Front Matter 和 GitHub Alerts 等专业扩展。
6. Markdown 中无法识别或暂不支持的语法必须以原始文本安全显示并完整保留，不能静默删除内容。

### 6.2 所见即所得与源码编辑

1. 默认提供 Markdown 所见即所得编辑模式，用户可以直接对渲染后的标题、列表、引用、表格、代码块等内容进行编辑。
2. 同时提供 Markdown 源码模式，用户可以随时查看和编辑完整原文。
3. 两种模式必须双向同步，切换模式、只读查看或打开历史轮次不能造成内容丢失。
4. 数据层始终以 Markdown 原文作为唯一内容来源，不以生成后的 HTML 或专有富文本格式保存提示词。
5. 仅切换模式不得改写 Markdown 原文；在所见即所得模式中实际编辑后，可以规范化等价的 Markdown 标记，但不得改变文本语义、代码内容、链接地址、列表层级或表格数据。
6. 提供常见格式工具栏和常规 Markdown 编辑快捷键，但界面保持简洁，不强制用户学习 Markdown 语法。
7. 中文输入法组合输入、撤销恢复、选区、光标位置、复制和粘贴在两种模式下都必须正常工作；输入法候选尚未上屏时不得保存不完整的组合文本。
8. “复制当前轮”和“复制全部”默认复制 Markdown 原文，保证粘贴到其他 AI 或编程工具后结构不变。
9. 所见即所得解析失败时必须保留原始 Markdown，停止覆盖保存并自动提供源码模式进行查看和修复。

### 6.3 代码块与安全渲染

1. 围栏代码块支持语言标记和常见编程语言的离线语法高亮；未知语言按纯文本正常显示。
2. 代码块必须保留空格、缩进、Tab、换行和长行内容。
3. 每个代码块提供独立复制按钮，复制时只复制代码正文。
4. 长代码行支持横向滚动或用户控制的自动换行，不能撑破界面。
5. 代码高亮样式必须同时适配深色和全部浅色主题。
6. Markdown 原始 HTML 仅允许经过严格安全过滤后的常见标签；脚本、事件属性、iframe、危险协议和其他可执行内容一律禁止。
7. Markdown 图片语法予以识别并保留，但首个版本不提供图片粘贴、上传、附件存储或图片管理。
8. 远程图片默认只显示占位信息和替代文本，不自动联网加载；用户主动点击后才允许临时加载该图片。
9. 所有 Markdown 渲染、代码高亮、样式和字体资源随软件本地提供，不使用 CDN。

### 6.4 长提示词折叠与详情查看

1. 历史轮次在时间线中默认显示为紧凑预览，默认展示 5 个视觉文本行。
2. 用户可以在设置中调整默认预览行数，至少支持 1～20 行和“不折叠”，设置全局生效并自动保存。
3. 预览行数以界面渲染后的视觉行数计算，不以 Markdown 原文中的换行符数量计算。
4. 折叠预览仍按 Markdown 安全渲染，超出部分隐藏，并显示渐隐效果和明确的“展开”入口。
5. 为避免展开长内容挤走后续轮次，点击轮次或“展开”后，在固定详情区域显示该轮完整内容，不在原位置将卡片无限撑高。
6. 宽窗口使用右侧详情面板；窄窗口使用覆盖式详情抽屉。
7. 打开或关闭详情时，时间线中其他轮次的高度、展开状态、顺序和滚动位置不得改变。
8. 详情区域支持完整阅读、所见即所得编辑、源码编辑、复制和收起；按 `Esc` 可以关闭并将焦点返回原轮次。
9. 当前草稿可以自动显示在详情编辑区域，历史轮次继续保持紧凑预览。
10. 提供一键收起详情的操作。

### 6.5 左侧时间线、保存时间与轮次序号

1. 当前项目内容区采用左侧轮次时间线和右侧详情区域；项目列表仍作为最左侧的独立导航区域。
2. 时间线按当前排列顺序展示每一轮提示词，并为每轮记录创建时间、首次保存为正式轮次的时间和最后修改时间。
3. 正式轮次主要显示完整保存时间；后续编辑过的轮次补充显示最后修改时间。
4. 当前草稿显示“草稿”和最近一次自动保存时间。
5. 时间使用系统本地时区；简略显示时，鼠标悬停必须能够看到包含日期和秒数的完整时间。
6. 调整轮次顺序不得修改该轮原始保存时间。
7. 提供“显示轮次序号”开关，默认开启并自动记忆。
8. 序号使用高对比度圆形或圆角徽标显示；当前选中轮次使用主题强调色突出显示。
9. 页面明显位置显示“当前：第 N 轮 / 共 M 轮”。
10. 显示序号代表当前排列中的位置；删除或调整顺序后自动重新编号，数据定位仍使用不会变化的内部 ID。

### 6.6 回到顶部与顺滑导航

1. 时间线滚动超过一个窗口高度后，显示悬浮的“一键回到顶部”按钮。
2. 回到顶部只改变当前项目时间线的浏览位置，不改变当前轮内容、编辑状态或选中状态。
3. 鼠标滚轮使用系统原生滚动，不使用容易产生延迟或滚动冲突的强制接管方案。
4. 时间线或轮次卡片获得焦点时，`↑`、`↓` 可以连续定位上一轮和下一轮，并自动将目标轮次平滑带入可视区域。
5. 时间线支持 `PageUp`、`PageDown` 翻页，并支持 `Home`、`End` 定位首轮和末轮。
6. 编辑器获得焦点时，方向键、`Home` 和 `End` 必须保持正常的文字光标功能，不能被全局轮次导航拦截。
7. 鼠标点击、滚轮和键盘切换后，当前轮必须具有一致且明显的选中反馈。
8. 软件应记忆每个项目的时间线位置；重新进入项目后恢复到上次轮次和浏览位置。
9. 程序化定位使用短而自然的平滑动画；Windows 开启“减少动画”时改为即时定位。

## 七、便携版交付

1. 首个版本只交付免安装便携版，不制作安装程序。
2. 当前个人精简版在已安装 Microsoft Edge WebView2 Runtime 的受支持 Windows 上，用户解压后可以直接运行主 EXE，不要求管理员权限，不强制写入注册表。当前目标电脑已经具备该运行时。
3. 程序设置、项目数据和自动备份默认保存在程序同目录的专用数据文件夹中，移动整个程序目录即可一并迁移数据。
4. 首次运行时自动创建所需数据目录，不覆盖同目录中的其他文件。
5. 当程序目录不可写时，必须使用简体中文明确提示并让用户选择可写的数据目录，不能静默丢失内容。
6. 移动或复制便携版目录应在软件完全退出后进行。
7. 软件运行时的核心功能无需联网，不能在首次启动时临时下载 Markdown 渲染器、代码高亮包或其他业务依赖。
8. 如果未来移动到缺少 WebView2 Runtime 的电脑，精简版只显示原生中文说明并安全退出，不静默联网下载；需要完全不依赖系统 WebView2 的场景另行制作体积显著更大的完整离线便携包，不属于当前个人首版交付。

## 十七、最终使用流程

1. 打开软件。
2. 进入上次使用的项目，或创建一个新项目。
3. 默认在 Markdown 所见即所得模式中编写第一轮提示词，必要时切换源码模式。
4. 一键复制并粘贴到任意 Vibe Coding 工具。
5. 完成一轮对话后，一键创建下一轮。
6. 继续编写并保存后续提示词。
7. 通过左侧时间线、显眼轮次序号和折叠预览有序浏览大量历史内容。
8. 点击任意轮次后，在不扰动时间线位置的详情区域中阅读、编辑、复制、排序或撤销内容。
9. 使用鼠标滚轮、键盘方向键或一键回到顶部快速定位轮次。
10. 所有数据自动保存并保留在便携版数据目录中。

## 0.1.1 实现与交付补充

以下补充用于消除需求之间或旧执行文档中的歧义，不改变上文既有需求编号：

- 数据安全优先：回收站不自动过期或在启动时永久清理；永久删除只由用户在最近删除中逐项确认。
- 渲染层不得向 Rust 指定任意输出路径。Markdown、项目包、完整备份和恢复文件的输出目标由 Rust 原生保存对话框产生；导入/恢复仍只读取用户明确选择的文件。
- 设置采用 `formatVersion = 1` 和字段级 patch；未知字段拒绝，损坏值先备份为 `settings.broken.*` 后安全降级，未来格式版本不得被旧程序覆盖。
- Markdown 安全分析必须离开输入主线程；超大或高风险内容保持原文并进入源码安全模式。代码高亮超限时完整显示纯文本，不为高亮牺牲输入响应。
- 活动 SQLite 数据目录拒绝 UNC 网络路径；同步目录只警告。远程图片为保持 DNS 固定和逐跳 SSRF 校验而不使用系统代理。
- 外部验收仍包括：五档真实 Windows DPI、真人微软拼音候选窗、Win10 22H2/另一台 Win11 冷热启动与恢复、WebView2 物理缺失场景。当前个人自用成品可以使用，但公开分发前必须完成这些项目及代码签名/字体授权复审。
- 0.1.1 收尾复核再次通过 102 项 Vitest、66 项 Rust、14 项 Playwright、Web/桌面构建、便携包逐文件校验、ZIP 外层哈希对照和原生隔离安全关闭冒烟；10 项 Playwright 按视口设计跳过，另有 1 项手动 Rust 性能入口按设计 ignored。

## 0.1.2 实现与交付补充

以下补充记录本轮生产级复核后的既有需求落地方式，不扩展产品范围：

- 待恢复状态必须能被用户明确取消；恢复、取消、重试和下次启动切换互斥，任何失败都不得以空库或静默清理替代可恢复现场。
- Rust、SQLite 和磁盘仍是持久化事实来源；仅复制正在编辑的当前轮次时允许读取尚未落盘的编辑缓冲，并明确把它作为用户当前可见内容复制，不改变数据库 revision 语义。
- 可读 Markdown 导出必须兼容零正式轮次、空草稿、Windows UTF-16 文件名长度、保留设备名、控制字符以及 Markdown/URL 转义；结构化项目包和完整备份格式保持 v1。
- 超过 2 MiB 的安全预览采用最多 256 Ki UTF-16 单元的有界纯文本展示，完整内容仍由编辑器、Rust 和 SQLite 保持；不得在主线程生成无界 Markdown DOM。
- 任何成功的数据变更都会重新评估自动备份时机；当前编辑必须先等待对应编辑序列落盘。频繁变更以 5 秒防抖合并，不让备份阻塞每次击键。
- 窄窗口和 Windows 缩放等效布局必须保持编辑模式控件可用且无横向溢出；嵌套弹窗只有最上层可被辅助技术识别为模态。
- 本轮本机自动验证为 130 项 Vitest、72 项 Rust、19 项 Playwright 通过，23 项 Playwright 按视口/场景设计跳过，另有 1 项手动 Rust 性能入口按设计 ignored；多台 Windows 实机、五档真实 DPI、真人微软拼音和物理缺失 WebView2 保持外部待验。

## 0.1.4 审查修复补充

以下补充记录逐项核实审查报告后的安全与一致性边界，不改变产品范围：

- 完成轮次必须先把保存循环追平到最新输入，真正切换数据库状态前才锁定；正常关闭必须先截断 WAL，并用单调 generation 防止迟到 IPC 把强退误记为安全退出。
- 活动数据根同时拒绝 UNC 与映射网络驱动器；WebView2 启动清理仅限固定可再生缓存白名单，不触碰登录、Local Storage、Preferences 等持久状态。
- 已导入字体在启动暴露前校验完整 SHA-256，字体解析迁移到维护中的 Fontations；Windows 同时枚举 32/64 位字体注册表视图。
- Markdown、项目包、完整备份和字体的本地读取路径只由 Rust 原生文件选择器产生，renderer 不再拥有文件打开权限。
- 备份恢复除结构、哈希、完整性和外键外，还验证项目、轮次、草稿、排序、时间、revision、视图引用和 FTS 原文一致性。
- 自动备份去重只认可 manifest 有效且内部时间属于当天/当周的真实归档；损坏文件或伪造名称不会阻断新备份。
- 远程 AVIF 在缺少受信有界解析器时明确拒绝；个人自用成品仍如实标记未签名，不用自签名冒充公开分发信任。
